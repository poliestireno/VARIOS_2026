Sesión en PHP I

Identificar a un usuario a lo largo de varias páginas: tabla de usuarios, formulario de login y la superglobal $_SESSION.

2 horas Sesión 10/13 Requiere base de datos ▶ Vídeo de la clase

El problema: HTTP no recuerda nada

Cada vez que el navegador pide una página PHP, es una petición nueva y completamente aislada de la anterior — PHP no sabe “quién” la pidió, ni si es la misma persona que cargó la página de antes. La sesión es el mecanismo que resuelve esto: PHP guarda un identificador único en una cookie del navegador, y usa ese identificador para recuperar datos guardados en el servidor entre una petición y la siguiente.

<?php
session_start(); // tiene que ir en la primera línea de CADA página que use $_SESSION
?>
session_start() antes que cualquier otra cosa

session_start() envía una cabecera HTTP (la cookie), y en PHP ninguna cabecera se puede enviar después de que ya haya salido algo de HTML — ni siquiera un espacio en blanco antes del <?php de apertura. Es el error más común de esta sesión: “headers already sent”. Solución: session_start() siempre en la primerísima línea del archivo.

Tabla de usuarios

Nunca se guarda una contraseña tal cual en la base de datos — se guarda su hash, el resultado de una función que la transforma en un texto irreversible. PHP trae password_hash() y password_verify() preparadas exactamente para esto.

CREATE TABLE usuarios (
  id INT AUTO_INCREMENT PRIMARY KEY,
  usuario VARCHAR(50) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL
);

Para crear el primer usuario de prueba, genera el hash desde PHP (no lo escribas a mano en phpMyAdmin) y guarda el resultado:

<?php
// crear_usuario.php -- lo ejecutas una vez y luego lo borras o comentas
require 'conexion.php';

$hash = password_hash("1234", PASSWORD_DEFAULT);

$stmt = $pdo->prepare("INSERT INTO usuarios (usuario, password_hash) VALUES (?, ?)");
$stmt->execute(["ana", $hash]);

echo "Usuario creado. Hash: " . $hash;

password_hash() genera un hash distinto cada vez, aunque la contraseña sea siempre "1234" — es intencionado (incluye un “salt” aleatorio) y no afecta a que password_verify() lo siga reconociendo como válido.

Formulario de login

<!-- login.php -->
<form action="procesar_login.php" method="post">
  <input type="text" name="usuario" placeholder="Usuario">
  <input type="password" name="password" placeholder="Contraseña">
  <button type="submit">Entrar</button>
</form>

Validar credenciales: login OK y KO

<?php
// procesar_login.php
session_start();
require 'conexion.php';

$stmt = $pdo->prepare("SELECT * FROM usuarios WHERE usuario = ?");
$stmt->execute([$_POST['usuario']]);
$usuario = $stmt->fetch(PDO::FETCH_ASSOC);

if ($usuario && password_verify($_POST['password'], $usuario['password_hash'])) {
  // login OK
  $_SESSION['usuario_id'] = $usuario['id'];
  $_SESSION['usuario_nombre'] = $usuario['usuario'];
  header("Location: app.php");
} else {
  // login KO
  header("Location: login.php?error=1");
}
exit;

Fíjate que la consulta busca solo por usuario, nunca por password directamente — no se puede comparar una contraseña en texto contra un hash con = en SQL. La comparación real ocurre en PHP, con password_verify(), que sí sabe cómo comprobar un texto contra su hash.

Un solo mensaje de error para los dos casos

Tanto si el usuario no existe ($usuario es false) como si existe pero la contraseña no coincide, se redirige al mismo login.php?error=1. Es a propósito: si el mensaje dijera “ese usuario no existe” frente a “contraseña incorrecta”, cualquiera podría usar el formulario para averiguar qué nombres de usuario están registrados.

Práctica

1

Crea la tabla y un usuario de prueba

Tabla usuarios y el script crear_usuario.php de arriba, con un usuario y contraseña a tu elección.

2

login.php y procesar_login.php

El formulario y el script que valida credenciales, tal como se ha visto hoy.

3

app.php

Una página sencilla que, si el login fue correcto, saluda por su nombre: "Bienvenido, " . $_SESSION['usuario_nombre']. Todavía sin protegerla contra accesos sin login — eso lo añadimos en la sesión 11.

4

Muestra el error en login.php

Si la URL trae ?error=1, muestra un mensaje (“Usuario o contraseña incorrectos”) encima del formulario.

<?php if (isset($_GET['error'])): ?>
  <p style="color:red">Usuario o contraseña incorrectos</p>
<?php endif; ?>
