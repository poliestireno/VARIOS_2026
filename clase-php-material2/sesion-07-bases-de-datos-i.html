Bases de datos en PHP I

Conectar PHP con una base de datos MySQL real y traer los primeros datos — con PDO y sentencias preparadas desde el primer día.

Crea la base de datos

Con Apache y MySQL arrancados en XAMPP, abre http://localhost/phpmyadmin. Crea una base de datos llamada curso_php y, dentro, ejecuta este script en la pestaña SQL para crear la tabla que usaremos en las tres próximas sesiones:

CREATE TABLE productos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  categoria VARCHAR(50) NOT NULL,
  precio DECIMAL(6,2) NOT NULL
);

Conexión con PDO

PDO (PHP Data Objects) es la forma moderna y recomendada de hablar con una base de datos desde PHP — funciona igual para MySQL, PostgreSQL o SQLite, cambiando solo la primera línea.

<?php
// conexion.php
try {
  $pdo = new PDO("mysql:host=localhost;dbname=curso_php;charset=utf8mb4", "root", "");
  $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
  die("Error de conexión: " . $e->getMessage());
}

"root" y "" (usuario y contraseña vacía) son las credenciales por defecto de MySQL en XAMPP. ERRMODE_EXCEPTION hace que cualquier error de base de datos lance una excepción de PHP en vez de fallar en silencio — igual de importante que activar display_errors en la sesión 1.

Un solo archivo de conexión

Guarda este código en su propio archivo, conexion.php, y a partir de ahora, en cada página que necesite la base de datos, empieza con require 'conexion.php';. Así solo tienes las credenciales escritas en un sitio.

Consultar con SELECT

Para una consulta fija, sin datos externos de por medio, query() es lo más directo:

$resultado = $pdo->query("SELECT * FROM productos");
$productos = $resultado->fetchAll(PDO::FETCH_ASSOC);

foreach ($productos as $producto) {
  echo $producto['nombre'] . " - " . $producto['precio'] . " €<br>";
}

fetchAll(PDO::FETCH_ASSOC) devuelve exactamente lo que viste en la sesión 5: un array de arrays asociativos, uno por fila, cada uno con las columnas como claves. Todo lo que aprendiste sobre foreach sobre arrays multidimensionales se aplica tal cual.

Sentencias preparadas

En cuanto un valor de la consulta viene de fuera (un formulario, la URL…), query() ya no es seguro: si simplemente concatenas ese valor dentro del SQL, alguien podría escribir algo en el formulario que cambie el significado de la consulta — es el ataque conocido como inyección SQL.

// ❌ NUNCA hagas esto con un valor que venga de fuera
$pdo->query("SELECT * FROM productos WHERE categoria = '" . $_GET['categoria'] . "'");

La solución son las sentencias preparadas: en vez de meter el valor directamente en el texto SQL, dejas un marcador (? o :nombre) y se lo pasas aparte con execute(). PDO se encarga de que ese valor nunca se interprete como parte del SQL.

$stmt = $pdo->prepare("SELECT * FROM productos WHERE categoria = ?");
$stmt->execute([$_GET['categoria']]);
$productos = $stmt->fetchAll(PDO::FETCH_ASSOC);
Regla de la clase

A partir de hoy: query() solo para SQL fijo, escrito por ti, sin ningún valor externo dentro. En cuanto aparezca un valor de $_GET, $_POST o cualquier otro origen externo, siempre prepare() + execute().

Reto extra

Añade una condición con dos marcadores: productos de una categoría y con precio menor que un valor dado (WHERE categoria = ? AND precio < ?), pasando ambos valores en el array de execute(), en el mismo orden que los ?.
