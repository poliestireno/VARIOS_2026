Bases de datos en PHP III

Cerrar el ciclo completo: insertar, modificar y borrar filas — siempre con sentencias preparadas, como en las dos sesiones anteriores.

2 horas Sesión 9/13 Sin instalar nada nuevo

INSERT: dar de alta

$stmt = $pdo->prepare("INSERT INTO productos (nombre, categoria, precio) VALUES (?, ?, ?)");
$stmt->execute([
  $_POST['nombre'],
  $_POST['categoria'],
  $_POST['precio'],
]);

echo "Producto creado con id " . $pdo->lastInsertId();

lastInsertId() devuelve el id que MySQL acaba de generar automáticamente para la fila nueva (gracias a AUTO_INCREMENT en la definición de la tabla) — útil para, por ejemplo, redirigir directamente a la ficha del producto recién creado.

UPDATE: modificar

Un UPDATE sin WHERE modifica todas las filas de la tabla — el WHERE id = ? aquí no es opcional.

$stmt = $pdo->prepare("UPDATE productos SET nombre = ?, categoria = ?, precio = ? WHERE id = ?");
$stmt->execute([
  $_POST['nombre'],
  $_POST['categoria'],
  $_POST['precio'],
  $_POST['id'],
]);

El id del producto a editar suele viajar como campo oculto del formulario (<input type="hidden" name="id" value="...">), rellenado al cargar la página de edición con los datos actuales de ese producto.

DELETE: borrar

$stmt = $pdo->prepare("DELETE FROM productos WHERE id = ?");
$stmt->execute([$_POST['id']]);
Borrar solo con POST, nunca con un enlace GET

Un enlace <a href="borrar.php?id=3"> parece más simple, pero es una trampa: cualquier cosa que visite esa URL (un bot, el propio navegador precargando enlaces) borraría la fila sin que nadie lo haya pedido de verdad. Un borrado siempre debería ir en un formulario con method="post" y, lo veremos en el bloque 4, protegido además por sesión.

Un solo archivo para las tres operaciones

En vez de tres páginas sueltas, es habitual centralizar altas, ediciones y borrados en un único gestionar.php que decide qué hacer según un campo accion del formulario:

$accion = $_POST['accion'] ?? '';

if ($accion === 'crear') {
  // ... INSERT
} elseif ($accion === 'editar') {
  // ... UPDATE
} elseif ($accion === 'borrar') {
  // ... DELETE
}

header("Location: listado.php"); // vuelve al listado tras cualquiera de las tres
exit;

header("Location: ...") le dice al navegador que cargue otra página — es la forma de redirigir desde PHP. Tiene una condición importante: tiene que ejecutarse antes de que el script haya enviado ya algo de HTML, o PHP dará un error. El exit; después es buena práctica: evita que el resto del script se siga ejecutando tras la redirección.

Práctica

Sobre el listado.php de la sesión anterior:

1

Formulario de alta

nuevo.php, con un formulario (nombre, categoría, precio) que envía por POST a gestionar.php con accion = "crear".

2

Botón de editar por fila

En cada fila de la tabla, un enlace a editar.php?id=... que carga ese producto, rellena un formulario con sus datos actuales y lo envía (por POST) a gestionar.php con accion = "editar".

3

Botón de borrar por fila

Un formulario pequeño (sin más campos que el id oculto) que envía por POST a gestionar.php con accion = "borrar".

Reto extra

Antes de borrar, pide confirmación en el propio navegador con onsubmit="return confirm('¿Seguro?')" en el formulario de borrado — evita borrados accidentales por un clic de más.
