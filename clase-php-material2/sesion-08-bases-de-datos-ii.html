Bases de datos en PHP II

Mostrar los resultados de una consulta en una tabla HTML de verdad, y filtrarlos con un formulario que el usuario rellena.

2 horas Sesión 8/13 Sin instalar nada nuevo

De array a tabla HTML

Es la misma idea que la matriz de la sesión 4: un bucle que recorre el array de productos y, por cada uno, imprime una fila <tr>.

<table border="1">
  <tr><th>Nombre</th><th>Categoría</th><th>Precio</th></tr>
  <?php foreach ($productos as $p): ?>
    <tr>
      <td><?php echo $p['nombre']; ?></td>
      <td><?php echo $p['categoria']; ?></td>
      <td><?php echo $p['precio']; ?> €</td>
    </tr>
  <?php endforeach; ?>
</table>
htmlspecialchars() para texto que viene de fuera

Si el texto de una celda puede contener lo que haya escrito un usuario (no es el caso de estos datos de ejemplo, pero sí lo será en el bloque 4), envuélvelo en htmlspecialchars($p['nombre']) antes de imprimirlo. Evita que alguien escriba código HTML o <script> en un campo de texto y acabe ejecutándose en la página de otro usuario — un ataque llamado XSS.

Un formulario de filtro

Un formulario de filtro típico usa method="get" (no post): así la URL resultante, con los filtros incluidos, se puede copiar, compartir o guardar en favoritos.

<form method="get">
  <input type="text" name="categoria" placeholder="Categoría"
         value="<?php echo $_GET['categoria'] ?? ''; ?>">
  <input type="number" name="precio_max" placeholder="Precio máximo"
         value="<?php echo $_GET['precio_max'] ?? ''; ?>">
  <button type="submit">Filtrar</button>
</form>

Rellenar de nuevo el value de cada campo con lo que ya había en $_GET es un detalle pequeño pero importante: sin él, cada vez que filtras, el formulario se vacía visualmente aunque el filtro siga aplicado — confuso para quien lo usa.

Construir la consulta según los filtros recibidos

El reto real de esta sesión: los dos filtros son opcionales, el usuario puede rellenar uno, otro, los dos o ninguno. La consulta SQL tiene que adaptarse a cada caso, siempre con sentencias preparadas.

$sql = "SELECT * FROM productos WHERE 1 = 1";
$parametros = [];

if (!empty($_GET['categoria'])) {
  $sql .= " AND categoria = ?";
  $parametros[] = $_GET['categoria'];
}

if (!empty($_GET['precio_max'])) {
  $sql .= " AND precio <= ?";
  $parametros[] = $_GET['precio_max'];
}

$stmt = $pdo->prepare($sql);
$stmt->execute($parametros);
$productos = $stmt->fetchAll(PDO::FETCH_ASSOC);

El truco es WHERE 1 = 1: una condición siempre verdadera, que te permite encadenar cualquier número de AND después (incluido ninguno) sin tener que comprobar si hace falta escribir la palabra WHERE o no. El array $parametros crece en el mismo orden que los ? que vas añadiendo al SQL — ese orden tiene que coincidir siempre.

Por qué empty() y no isset()

isset($_GET['categoria']) es true incluso si el usuario dejó el campo vacío y solo pulsó “Filtrar” (el campo sí llega, pero con valor ""). empty() trata la cadena vacía como “no hay filtro”, que es lo que de verdad quieres aquí.

Práctica

Amplía el listado.php de la sesión anterior:

1

Muestra los productos en una tabla HTML

Con las columnas nombre, categoría y precio, como en el primer ejemplo de hoy.

2

Añade el formulario de filtro

Por categoría y por precio máximo, encima de la tabla, con los valores conservados entre recargas.

3

Construye la consulta dinámicamente

Con el patrón WHERE 1 = 1 + AND condicionales de arriba, para que los dos filtros sean opcionales e independientes.

Reto extra

Si la consulta no devuelve ningún producto, muestra un mensaje (“No hay productos con esos filtros”) en vez de una tabla vacía — comprueba count($productos) === 0 antes de dibujar la tabla.
