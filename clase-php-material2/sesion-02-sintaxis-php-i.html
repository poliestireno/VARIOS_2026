Variables y tipos de datos

En PHP, toda variable empieza con el símbolo $ — no hace falta ninguna palabra como let o const, el propio $ ya indica “esto es una variable”. PHP no obliga a declarar el tipo: lo decide solo, según el valor que le asignes.

$edad = 32;             // int
$precio = 19.90;        // float
$nombre = "Ana";        // string
$activo = true;        // bool
$sinValor = null;      // null

echo gettype($edad);      // "integer"
var_dump($precio);       // float(19.9)

gettype() devuelve el tipo como texto; var_dump() es más completo — muestra el tipo y el valor, y es la herramienta que más vas a usar para depurar mientras aprendes, mucho más útil que echo cuando no estás seguro de qué contiene realmente una variable.

PHP es de tipado dinámico

Una misma variable puede cambiar de tipo en cualquier momento: $x = 5; $x = "cinco"; es perfectamente válido, el segundo $x ya es un string. Es cómodo para ir rápido, pero también la fuente de errores más habitual de quien empieza — comparar un número con el texto que lo representa (por ejemplo, un valor que llega de $_POST) es más delicado de lo que parece, como viste en la sesión 1.

Operadores

Los aritméticos son los mismos que en cualquier calculadora, incluido el módulo (resto de una división) que usarás mucho en ejercicios de control de flujo:

echo 10 + 3;  // 13
echo 10 % 3;  // 1  -> resto de la división
echo 2 ** 3;  // 8  -> potencia

Para unir texto, PHP usa el punto (.), no el +:

$nombre = "Ana";
echo "Hola, " . $nombre . "!"; // "Hola, Ana!"

// atajo: incrustar la variable directamente dentro de un string con comillas dobles
echo "Hola, $nombre!"; // mismo resultado, más corto
Comillas simples vs dobles

Con comillas dobles ("$nombre"), PHP sustituye la variable por su valor. Con comillas simples ('$nombre'), no — se imprime literalmente el texto $nombre. Es la trampa más común de quien viene de JavaScript, donde las comillas simples y dobles se comportan siempre igual.

Los de comparación tienen la misma trampa que en JavaScript, y la misma solución:

var_dump("5" == 5);   // true  -> compara solo el valor, convierte tipos
var_dump("5" === 5);  // false -> compara valor Y tipo
var_dump(0 == "texto"); // false en PHP 8 (en PHP 7 daba true)

Norma de la clase, igual que en JavaScript: usa siempre === y !==, nunca == ni !=, salvo que tengas una razón muy concreta para querer la conversión automática de tipos.

Constantes

Una constante es como una variable que no puede cambiar de valor una vez definida — y, a diferencia de las variables, no lleva $.

define('IVA', 0.21);
const NOMBRE_APP = 'Gestor de tareas';

echo IVA;          // 0.21
echo NOMBRE_APP;   // "Gestor de tareas"

define() y const hacen prácticamente lo mismo; la diferencia práctica es que const se evalúa al cargar el script (no puedes usarla dentro de un if) mientras que define() es una función normal, y por tanto más flexible. Para constantes sencillas de configuración, cualquiera de las dos vale.

Funciones

Se declaran con function, reciben parámetros entre paréntesis y devuelven un valor con return:

function saludar($nombre, $saludo = "Hola") {
  return "$saludo, $nombre!";
}

echo saludar("Ana");           // "Hola, Ana!"
echo saludar("Luis", "Buenas"); // "Buenas, Luis!"

$saludo = "Hola" es un valor por defecto: si no se pasa ese segundo argumento, la función usa "Hola" automáticamente. Los parámetros con valor por defecto siempre van al final de la lista.

Paso por valor y por referencia

Por defecto, PHP pasa los parámetros por valor: la función recibe una copia, y modificarla dentro no afecta a la variable original.

function duplicar($numero) {
  $numero = $numero * 2;
}

$x = 5;
duplicar($x);
echo $x; // 5 -> no ha cambiado, "duplicar" trabajó sobre una copia

Para que la función sí pueda modificar la variable original, se pasa por referencia, añadiendo & delante del parámetro:

function duplicarDeVerdad(&$numero) {
  $numero = $numero * 2;
}

$x = 5;
duplicarDeVerdad($x);
echo $x; // 10 -> esta vez sí ha cambiado
Cuándo usar cada uno

Casi siempre quieres por valor (el comportamiento por defecto): es más predecible, porque la función no tiene efectos secundarios fuera de lo que devuelve con return. Usa por referencia solo cuando de verdad necesites que una función modifique varias variables externas a la vez — es justo el caso del ejercicio de hoy.

Práctica

Escribe una función calcular($a, $b, $operador, &$resultado) que:

1

Reciba tres operandos…

Bueno, en realidad dos números ($a, $b) y un operador en texto ($operador, por ejemplo "+", "-", "*" o "/").

2

…y devuelva el resultado por referencia

En vez de un return, la función escribe el resultado directamente en el cuarto parámetro, &$resultado, que se pasa por referencia.

function calcular($a, $b, $operador, &$resultado) {
  if ($operador === "+") {
    $resultado = $a + $b;
  } elseif ($operador === "-") {
    $resultado = $a - $b;
  }
  // completa "*" y "/" tú mismo
}

$total = 0;
calcular(4, 5, "+", $total);
echo $total; // 9
Reto extra

Controla la división por cero: si $operador es "/" y $b es 0, guarda en $resultado el texto "Error: división por cero" en vez de intentar dividir.
