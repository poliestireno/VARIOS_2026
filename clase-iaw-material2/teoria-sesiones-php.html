01

El problema: HTTP no recuerda nada

Cada petición HTTP es independiente de la anterior — el servidor, por sí solo, no sabe que dos peticiones seguidas vienen del mismo navegador. Las sesiones resuelven esto: PHP guarda una cookie con un identificador único en el navegador, y en el servidor asocia ese identificador a un array $_SESSION donde se puede guardar cualquier dato entre páginas.

session_start() antes que cualquier otra cosa

session_start() envía una cabecera HTTP (la cookie), y en PHP ninguna cabecera se puede enviar después de que ya haya salido algo de HTML — ni siquiera un espacio en blanco antes del <?php de apertura. Es el error más común: “headers already sent”. Solución: session_start() siempre en la primerísima línea de cada página que use $_SESSION.

02

Contraseñas: password_hash() y password_verify()

Nunca se guarda una contraseña tal cual en la base de datos — se guarda su hash, el resultado de una función que la transforma en un texto irreversible.

$hash = password_hash($_POST['password'], PASSWORD_DEFAULT);
$stmt = $pdo->prepare("INSERT INTO usuarios (usuario, password_hash, es_superusuario) VALUES (?, ?, ?)");
$stmt->execute([$_POST['usuario'], $hash, $_POST['superusuario'] ?? 0]);

password_hash() genera un hash distinto cada vez, aunque la contraseña sea siempre la misma — es intencionado (incluye un “salt” aleatorio) y no afecta a que password_verify() lo siga reconociendo como válido.

03

Formulario de login y validación

<?php
// procesar_login.php
session_start();
$stmt = $pdo->prepare("SELECT * FROM usuarios WHERE usuario = ?");
$stmt->execute([$_POST['usuario']]);
$usuario = $stmt->fetch(PDO::FETCH_ASSOC);

if ($usuario && password_verify($_POST['password'], $usuario['password_hash'])) {
  $_SESSION['usuario_id'] = $usuario['id'];
  $_SESSION['usuario_nombre'] = $usuario['usuario'];
  $_SESSION['es_superusuario'] = $usuario['es_superusuario'];
  $_SESSION['ultimo_acceso'] = time();
  header("Location: app.php");
} else {
  header("Location: login.php?error=1");
}
exit;

password_verify($password_en_claro, $hash_guardado) compara sin necesitar deshacer el hash — devuelve true/false.

04

Proteger páginas frente a accesos sin login

<?php
// requiere_login.php
session_start();
if (!isset($_SESSION['usuario_id'])) {
  header("Location: login.php");
  exit;
}
<?php
// app.php
require 'requiere_login.php'; // si no hay sesión, ya redirige y para todo lo demás
?>
<h1>Bienvenido, <?php echo $_SESSION['usuario_nombre']; ?></h1>

Centralizar la comprobación en requiere_login.php, en vez de repetir el if en cada página, significa que si mañana cambia la lógica (por ejemplo, se añaden roles) solo hay que tocar un archivo.

05

Expiración de la sesión por tiempo

Se guarda un “sello de tiempo” cada vez que el usuario hace algo, y se compara en cada petición con el momento actual. Si ha pasado demasiado tiempo, se cierra la sesión igual que con el botón de logout.

<?php
// requiere_login.php (con expiración)
session_start();
$limite = 300; // 5 minutos, en segundos

if (!isset($_SESSION['usuario_id'])) {
  header("Location: login.php");
  exit;
}

if (isset($_SESSION['ultimo_acceso']) && (time() - $_SESSION['ultimo_acceso'] > $limite)) {
  $_SESSION = [];
  session_destroy();
  header("Location: login.php?expirada=1");
  exit;
}

$_SESSION['ultimo_acceso'] = time(); // se actualiza en cada página protegida visitada

time() devuelve el instante actual en segundos. El límite es de inactividad, no de tiempo total conectado: si el usuario sigue navegando entre páginas protegidas, la sesión no caduca.

06

Cerrar sesión

Cerrar sesión es, básicamente, deshacer lo que session_start() montó: vaciar $_SESSION y destruir la sesión en el servidor.

<?php
// logout.php
session_start();
$_SESSION = [];
session_destroy();
header("Location: login.php");
exit;
07

Roles: superusuario y usuario normal

Con el rol guardado en $_SESSION al hacer login, cada página puede decidir qué mostrar sin volver a consultar la base de datos:

if ($_SESSION['es_superusuario']) {
  // ver todos los datos, modificar, borrar
} else {
  // vista limitada: solo lectura de lo permitido
}

Para una comprobación más estricta (por ejemplo, una página exclusiva de administración), se puede crear un segundo guion requiere_superusuario.php que, además de comprobar la sesión, verifique el rol y redirija si no coincide.
