01

Conexión con PDO

PDO (PHP Data Objects) es la forma moderna y recomendada de hablar con una base de datos desde PHP — funciona igual para MySQL, PostgreSQL o SQLite, cambiando solo la primera línea.

try {
  $pdo = new PDO("mysql:host=localhost;dbname=mi_bd;charset=utf8mb4", "root", "");
  $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
  die("Error de conexión: " . $e->getMessage());
}

ERRMODE_EXCEPTION hace que cualquier error SQL lance una excepción capturable, en vez de fallar en silencio.

02

Consultar con SELECT

$resultado = $pdo->query("SELECT * FROM productos");
$productos = $resultado->fetchAll(PDO::FETCH_ASSOC);

fetchAll(PDO::FETCH_ASSOC) devuelve un array de arrays asociativos, uno por fila, cada uno con las columnas como claves — se recorre con foreach exactamente igual que cualquier array multidimensional.

03

Sentencias preparadas

Cuando un valor externo ($_GET, $_POST…) entra en la consulta, query() ya no vale — abre la puerta a inyección SQL. La solución son las sentencias preparadas: en vez de meter el valor directamente en el texto SQL, se deja un marcador (?) y se pasa aparte con execute().

$stmt = $pdo->prepare("SELECT * FROM productos WHERE categoria = ?");
$stmt->execute([$_GET['categoria']]);
$productos = $stmt->fetchAll(PDO::FETCH_ASSOC);
Regla fija

query() solo para SQL fijo, escrito por ti, sin ningún valor externo dentro. En cuanto aparezca un valor de fuera, siempre prepare() + execute().

04

De array a tabla HTML

<table>
<?php foreach ($productos as $p): ?>
  <tr>
    <td><?php echo $p['nombre']; ?></td>
    <td><?php echo $p['precio']; ?></td>
  </tr>
<?php endforeach; ?>
</table>

La sintaxis alternativa foreach (...): ... endforeach; se usa casi siempre que se mezcla PHP con HTML en la misma plantilla — se lee mejor que anidar llaves entre etiquetas.

05

Formulario de filtro

Un formulario con method="get" envía sus campos como parte de la URL (?categoria=Informática) — cómodo para filtros, porque la URL resultante se puede compartir o recargar sin reenviar nada. La consulta se construye leyendo esos parámetros:

$sql = "SELECT * FROM productos WHERE 1=1";
$params = [];

if (!empty($_GET['categoria'])) {
  $sql .= " AND categoria = ?";
  $params[] = $_GET['categoria'];
}

$stmt = $pdo->prepare($sql);
$stmt->execute($params);

WHERE 1=1 es un truco habitual: permite encadenar AND condicionalmente, sin tener que comprobar si es el primer filtro o no.

06

INSERT: dar de alta

$stmt = $pdo->prepare("INSERT INTO productos (nombre, categoria, precio) VALUES (?, ?, ?)");
$stmt->execute([$_POST['nombre'], $_POST['categoria'], $_POST['precio']]);

echo "Creado con id " . $pdo->lastInsertId();

lastInsertId() devuelve el id generado automáticamente por AUTO_INCREMENT para la fila nueva.

07

UPDATE: modificar

Un UPDATE sin WHERE modifica todas las filas — el WHERE id = ? nunca es opcional.

$stmt = $pdo->prepare("UPDATE productos SET nombre = ?, precio = ? WHERE id = ?");
$stmt->execute([$_POST['nombre'], $_POST['precio'], $_POST['id']]);

El id a editar suele viajar como campo oculto (<input type="hidden" name="id">), rellenado con los datos actuales al cargar la página de edición.

08

DELETE: borrar

$stmt = $pdo->prepare("DELETE FROM productos WHERE id = ?");
$stmt->execute([$_POST['id']]);
Nunca con un enlace GET

Un <a href="borrar.php?id=3"> parece más simple, pero cualquier cosa que visite esa URL (un bot, el navegador precargando enlaces) borraría la fila sin que nadie lo pidiera de verdad. Un borrado siempre va en un formulario con method="post".

09

Un solo archivo para las tres operaciones

En vez de tres páginas sueltas, es habitual centralizar altas, ediciones y borrados en un único gestionar.php que decide qué hacer según un campo accion del formulario:

$accion = $_POST['accion'] ?? '';

if ($accion === 'crear') {
  // ... INSERT
} elseif ($accion === 'editar') {
  // ... UPDATE
} elseif ($accion === 'borrar') {
  // ... DELETE
}

header("Location: listado.php");
exit;

header("Location: ...") redirige el navegador — tiene que ejecutarse antes de que el script haya enviado ya algo de HTML. El exit; después evita que el resto del script siga ejecutándose tras la redirección.
