Fase 1 · Permisos de archivos en Linux

Ejercicio 1 · Gestión de permisos en un entorno de trabajo multiusuario

Escenario: eres el administrador de un equipo de desarrollo con varios usuarios, y necesitas configurar los permisos de un proyecto compartido entre tres usuarios: monon1, tronko2 y birmingan3. Cada uno debe tener permisos específicos para un directorio de proyecto, de acuerdo con su rol.

1.1

Crear el entorno simulado

Crea los tres usuarios y un grupo común llamado devEria2. Crea un directorio llamado di_recto para el proyecto y cambia su grupo propietario a devEria2.

1.2

Permisos básicos

Configura los permisos para que solo los usuarios del grupo devEria2 puedan escribir en el directorio. Verifica mostrando los permisos del directorio.

1.3

Permisos avanzados

monon1 debe tener permisos completos (lectura, escritura, ejecución) en todo el proyecto: cambia el propietario del directorio a monon1. Los otros dos usuarios del grupo solo deben poder leer y ejecutar archivos, pero no modificarlos: cambia los permisos de modo que el grupo devEria2 solo tenga permisos de lectura y ejecución.

Preguntas

¿Qué sucede si un usuario fuera del grupo devEria2 intenta acceder al directorio? ¿Qué sucede si tronko2 intenta modificar un archivo dentro del directorio?

Ejercicio 2 · Control de acceso con el bit SGID en directorios

Escenario: el equipo necesita colaborar en un subdirectorio dentro de di_recto. Queremos asegurarnos de que cualquier archivo creado en ese subdirectorio tenga automáticamente el mismo grupo propietario (devEria2), para facilitar la colaboración.

2.1

Crear el subdirectorio

Crea un subdirectorio llamado di_afano dentro de /di_recto y cambia su grupo propietario a devEria2.

2.2

Aplicar el bit SGID

Aplica el bit SGID al subdirectorio di_afano, para que todos los archivos creados en él hereden el grupo propietario. Verifica y muestra los permisos del subdirectorio.

2.3

Crear un archivo de prueba

Cambia al usuario tronko2 y crea un archivo llamado archivo_tronko2.txt dentro de di_afano. Verifica y muestra los permisos y el grupo propietario del archivo.

Preguntas

¿Cuál es el grupo propietario del archivo creado por tronko2? ¿Qué ventaja aporta el bit SGID en un entorno de colaboración?

Ejercicio 3 · Gestión de archivos temporales con sticky bit

Escenario: se ha creado un directorio temporal compartido entre todos los usuarios del sistema. Necesitas asegurarte de que los usuarios puedan crear y modificar sus propios archivos, pero no puedan eliminar o modificar los archivos de otros usuarios.

3.1

Crear el directorio temporal

Crea un directorio llamado tmp_rano en /tmp. Cambia los permisos para que todos los usuarios puedan leer, escribir y ejecutar en el directorio.

3.2

Aplicar el sticky bit

Aplica el sticky bit al directorio para evitar que los usuarios eliminen archivos de otros. Verifica los permisos del directorio.

3.3

Crear archivos de prueba

Cambia al usuario monon1 y crea un archivo en el directorio temporal. Cambia después a birmingan3 y verifica si puede eliminar el archivo de monon1.

Preguntas

¿Pudo birmingan3 eliminar el archivo de monon1? ¿Por qué? ¿Cómo ayuda el sticky bit a mejorar la seguridad en directorios compartidos?

Ejercicio 4 · Configuración de umask y creación de archivos nuevos

Escenario: quieres configurar el entorno de trabajo para que todos los archivos nuevos creados por los usuarios tengan permisos predeterminados restrictivos (solo lectura y escritura para el propietario, sin acceso para el grupo y otros).

4.1

Configurar umask

Verifica el valor actual de umask. Cámbialo a 077 para que los archivos creados sean accesibles solo por el propietario.

4.2

Crear archivos de prueba

Crea un archivo nuevo llamado gomaesp_umask y verifica sus permisos.

4.3

Restablecer umask

Restaura el valor predeterminado de umask (habitualmente 022).

Preguntas

¿Cómo afectó el valor de umask a los permisos de los nuevos archivos? ¿Cómo podrías usar umask para mejorar la seguridad de los archivos en un sistema multiusuario?

Ejercicio 5 · Implementación de ACLs

Escenario: queremos que birmingan3 pueda leer un archivo específico dentro de un nuevo directorio llamado archivos_criticos, pero sin poder modificarlo.

5.1

Habilita ACLs si hace falta

Comprueba si las ACL están habilitadas en el sistema de archivos; instala el paquete acl si no lo estuvieran ya (si ya lo están, omite este paso).

5.2

Crea el directorio y el archivo

Crea el directorio archivos_criticos y, dentro, un archivo con contenido de ejemplo.

5.3

Concede el permiso con setfacl

Usa setfacl para dar a birmingan3 permiso de solo lectura sobre ese archivo, sin cambiar el propietario ni el grupo. Verifica con getfacl que el permiso se ha aplicado correctamente, y comprueba que birmingan3 no puede escribir en el archivo.

Fase 2 · Reto de búsquedas avanzadas

Objetivo: uso efectivo de los comandos de búsqueda (grep, find, locate) y sus opciones para localizar información específica, archivos y directorios dentro del sistema de ficheros.

Setup inicial (en tu directorio personal) 
$ mkdir -p Documentos/Informes Documentos/Logs Proyectos/web Proyectos/app
$ touch Documentos/Logs/log_acceso.2023 Documentos/Logs/log_error.2024
$ touch Proyectos/web/index.html Proyectos/web/estilos.css
$ touch Proyectos/app/main.py Proyectos/app/config_dev.ini
$ touch Documentos/Informes/informe_final.txt

Rellena el contenido de estos tres archivos (con echo o un editor como nano):

# Documentos/Logs/log_error.2024
[CRIT] Error en la base de datos.
[WARN] Conexion lenta.
[CRIT] Fallo de autenticacion.
[INFO] Tarea completada.

# Proyectos/app/main.py
# Este es el script principal
PATH_CONFIG = '/etc/prod/config.ini' # Configuracion de produccion
def iniciar_servidor():
    pass
# Funcion obsoleta: iniciar_antiguo()

# Proyectos/app/config_dev.ini
[GENERAL]
DEBUG = True
PORT = 8080

I. Ejercicios con grep — búsqueda de contenido

I.1

Busca errores críticos

Muestra todas las líneas que contengan la palabra [CRIT] dentro de Documentos/Logs/log_error.2024.

I.2

Busca la configuración de producción

Dentro del directorio Proyectos, busca recursivamente (-r) en todos los archivos la cadena PATH_CONFIG.

I.3

Contar fallos

Muestra solo el número de líneas (-c) que contienen la palabra Fallo en log_error.2024.

I.4

Líneas sin comentarios

Muestra todas las líneas de Proyectos/app/main.py que no (-v) empiecen por el símbolo de comentario (#). Pista: usa la expresión regular ^# para indicar “empieza por #”.

II. Ejercicios con find — búsqueda de archivos por propiedad

II.1

Archivos de configuración

Busca todos los archivos que terminen con la extensión .ini en todo el directorio de la práctica.

II.2

Directorios específicos

Busca todos los elementos que sean directorios (-type d) y se llamen Logs.

II.3

Archivos grandes (simulación)

Ejecuta truncate -s 2M Documentos/Informes/informe_final.txt. Ahora busca todos los archivos (-type f) dentro de la práctica que sean mayores de 1 megabyte (-size +1M).

II.4

Archivos modificados recientemente

Busca todos los archivos (-type f) que hayan sido modificados (-mtime) en el último día (-1).

III. Ejercicios con locate — búsqueda rápida en base de datos

Nota

Si locate no encuentra los archivos recién creados, ejecuta sudo updatedb primero (si tienes permisos).

III.1

Búsqueda general

Busca rápidamente la ruta completa de todos los archivos que contienen la palabra config en su nombre.

III.2

Búsqueda sin distinción de mayúsculas

Busca el archivo informe_final.txt sin importar si el texto está en mayúsculas o minúsculas (-i).

Entrega: documento o repositorio con los comandos ejecutados en cada apartado, los pantallazos de verificación, y las respuestas a todas las preguntas planteadas (Fase 1 y Fase 2).
