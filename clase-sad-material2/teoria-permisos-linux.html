01

Notación de permisos

Cada fichero o directorio en Linux tiene tres niveles de permiso — propietario, grupo y otros — y tres tipos de permiso en cada nivel — lectura (r), escritura (w) y ejecución (x). Se leen con ls -l:

$ ls -l archivo
-rwxr-xr-x 1 usuario grupo 0 date archivo

Cada bloque de tres letras se traduce también a un número, sumando 4 (lectura) + 2 (escritura) + 1 (ejecución): rwx = 7, r-x = 5, r-- = 4, rw- = 6, etc. Así, 755 equivale a rwxr-xr-x.

02

chmod — cambiar permisos

El comando chmod cambia los permisos de un archivo o directorio, en modo numérico o simbólico.

$ chmod 755 archivo
# rwx para el propietario, r-x para grupo y otros
$ ls -l archivo
-rwxr-xr-x 1 usuario grupo 0 date archivo

$ chmod +x script.sh
# añade el permiso de ejecución al propietario
$ ls -l script.sh
-rwxr--r-- 1 usuario grupo 0 date script.sh
03

chown — cambiar propietario y grupo

El comando chown cambia el propietario y, opcionalmente, el grupo de un archivo o directorio.

$ chown usuario:grupo archivo
$ ls -l archivo
-rwxr--r-- 1 usuario grupo 0 date archivo

$ chown -R usuario:grupo /directorio
# -R: recursivo, afecta también a subdirectorios y ficheros
04

chgrp — cambiar el grupo

El comando chgrp cambia únicamente el grupo propietario de un archivo o directorio.

$ chgrp nombre_grupo archivo
$ chgrp -R nombre_grupo /directorio
05

umask — permisos por defecto

El comando umask establece los permisos con los que se crean, por defecto, los nuevos archivos y directorios — restando su valor de los permisos máximos (666 para ficheros, 777 para directorios).

$ umask 022
$ touch nuevo_archivo && ls -l nuevo_archivo
-rwxr-xr-x 1 usuario grupo 0 date nuevo_archivo

$ umask 007
$ touch otro_archivo && ls -l otro_archivo
-rwxrwx--- 1 usuario grupo 0 date otro_archivo

$ umask 002
$ touch nuevo_archivo && ls -l nuevo_archivo
-rwxrwxr-x 1 usuario grupo 0 date nuevo_archivo

$ umask -S
# muestra la umask actual en notación simbólica
u=rwx,g=rx,o=rx
06

SUID (Set User ID)

El bit SUID permite que un archivo ejecutable se ejecute con los permisos de su propietario, en vez de con los del usuario que lo está ejecutando. Se usa para que programas concretos puedan realizar tareas que requieren permisos de superusuario (root) sin dar al usuario ese acceso de forma permanente.

$ chmod u+s archivo
$ ls -l archivo
-rwsr--r-- 1 usuario grupo 0 date archivo
# la "s" sustituye a la "x" del propietario
07

SGID (Set Group ID)

El bit SGID se comporta de forma distinta según se aplique a un fichero o a un directorio:

  • En ficheros ejecutables: el fichero se ejecuta con los permisos del grupo propietario del archivo, en vez de con los del grupo del usuario que lo ejecuta.
  • En directorios: los archivos creados dentro de ese directorio heredan automáticamente el grupo del directorio, en vez del grupo del usuario que los crea — muy útil en entornos colaborativos.
$ chmod g+s directorio
$ ls -l directorio
drwxr-sr-x 1 usuario grupo 0 date directorio
# la "s" sustituye a la "x" del grupo
08

Sticky bit

El sticky bit se aplica normalmente a directorios compartidos por muchos usuarios, como /tmp. Con él activo, solo el propietario de cada archivo (o el superusuario) puede eliminarlo o renombrarlo — aunque otros usuarios tengan permiso de escritura sobre el directorio.

$ chmod +t directorio
$ ls -ld directorio
drwxr-xr-t 1 usuario grupo 0 date directorio
# la "t" sustituye a la "x" de otros
09

ACL — permisos avanzados

El esquema rwx solo distingue tres niveles: propietario, grupo y otros. Cuando hace falta dar un permiso concreto a un usuario o grupo adicional — sin que pertenezca al grupo propietario — se usan las ACL (Access Control List), permisos avanzados que se añaden por encima de los básicos.

$ sudo apt install acl
# instala setfacl / getfacl si no están ya disponibles

$ setfacl -m u:birmingan3:r archivo_critico.txt
# -m: modifica la ACL, añadiendo lectura para el usuario birmingan3

$ getfacl archivo_critico.txt
# muestra la lista completa de permisos ACL del archivo

$ setfacl -x u:birmingan3 archivo_critico.txt
# -x: elimina la entrada ACL de ese usuario

Un archivo con ACL añade un + al final de sus permisos en ls -l (por ejemplo -rw-r-----+), como aviso de que tiene permisos adicionales que no se ven en la notación básica.

10

grep — búsqueda de contenido

Busca texto dentro de archivos, línea a línea.

$ grep "[CRIT]" log_error.2024
# líneas que contienen la cadena

$ grep -r "PATH_CONFIG" Proyectos/
# -r: recursivo, en todos los archivos del árbol de directorios

$ grep -c "Fallo" log_error.2024
# -c: cuenta solo el número de líneas que coinciden

$ grep -v "^#" main.py
# -v: invierte la búsqueda (líneas que NO coinciden)
# ^# : expresión regular, "empieza por #"
11

find — búsqueda de archivos por propiedad

Recorre un árbol de directorios buscando archivos que cumplan ciertas condiciones: nombre, tipo, tamaño, fecha de modificación…

$ find . -name "*.ini"
# archivos cuyo nombre termina en .ini

$ find . -type d -name "Logs"
# -type d: solo directorios

$ find . -type f -size +1M
# -type f: solo ficheros; -size +1M: mayores de 1 megabyte

$ find . -type f -mtime -1
# modificados en el último día
12

locate — búsqueda rápida en base de datos

locate no recorre el disco en el momento de la búsqueda: consulta una base de datos indexada de antemano, por lo que es mucho más rápido que find — a cambio, si el archivo se acaba de crear puede no aparecer todavía.

$ sudo updatedb
# actualiza la base de datos si el archivo recién creado no aparece

$ locate config
# ruta completa de todos los archivos con "config" en el nombre

$ locate -i informe_final.txt
# -i: sin distinguir mayúsculas/minúsculas
