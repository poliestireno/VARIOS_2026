01

Estructura básica

Todo documento HTML5 empieza con el mismo esqueleto: el <!DOCTYPE html> le dice al navegador que interprete la página en modo estándar, y dentro de <html> se separan los metadatos (<head>) del contenido visible (<body>).

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi página</title>
</head>
<body>
  <h1>Hola</h1>
</body>
</html>

El lang="es" del <html> no es decorativo: se lo indica a lectores de pantalla y a herramientas de traducción. El viewport es imprescindible para que la página se vea bien en móvil — sin él, el navegador móvil simula una pantalla de escritorio y hace zoom-out.

Atajo en VS Code

Con la extensión Emmet (incluida por defecto en VS Code), escribe ! al principio de un archivo .html vacío y pulsa Tab — genera todo este esqueleto automáticamente.

02

Texto y semántica

Los encabezados (h1 a h6) forman una jerarquía — un único h1 por página, y el resto en orden descendente, sin saltarse niveles solo por el tamaño de letra. Los párrafos van en <p>, y las listas en <ul> (sin orden) u <ol> (numerada), cada elemento como <li>.

Además de las etiquetas de toda la vida (div, span), HTML5 añade etiquetas semánticas que describen el papel de cada bloque en vez de ser contenedores genéricos:

<header>Cabecera con el logo y el título</header>
<nav>Menú de navegación entre páginas</nav>
<main>
  <section>
    <h2>Un bloque temático</h2>
    <article>Contenido independiente (un post, una tarjeta)</article>
  </section>
</main>
<footer>Pie de página</footer>

Usarlas no cambia el aspecto visual (por defecto no llevan estilo propio), pero sí ayuda a lectores de pantalla, a buscadores, y a cualquiera que lea el código más tarde — incluido tú mismo dentro de una semana.

03

Enlaces y navegación

El enlace es la etiqueta <a> con un atributo href. Puede apuntar a otra página del propio sitio (ruta relativa), a una URL externa, o abrir en una pestaña nueva.

<a href="galeria.html">Ver galería</a>
<a href="index.html">← Volver al inicio</a>
<a href="fotos/playa.jpg" target="_blank">
  <img src="fotos/playa-mini.jpg" alt="Playa al atardecer">
</a>

El tercer ejemplo es un patrón habitual para una galería: una miniatura enlaza a la imagen a tamaño completo, abierta en una pestaña nueva (target="_blank") para no perder la página de índice.

04

Imágenes y multimedia

Una imagen es una etiqueta sin cierre, con src (la ruta) y alt (el texto alternativo, obligatorio por accesibilidad).

<img src="portada.jpg" alt="Portada del podcast" width="300">

Para reproducir audio o vídeo directamente en la página (sin depender de un reproductor externo), HTML5 trae etiquetas dedicadas:

<audio controls>
  <source src="episodio1.mp3" type="audio/mpeg">
  Tu navegador no soporta audio HTML5.
</audio>

<video controls width="480">
  <source src="clip.mp4" type="video/mp4">
</video>

El atributo controls añade los botones de reproducir/pausar/volumen sin escribir una sola línea de JavaScript. <source> permite ofrecer varios formatos del mismo archivo; el navegador usa el primero que entienda.

05

Tablas

Una tabla es una fila de encabezado (<th>) y filas de datos (<td>), todas dentro de <tr> (table row). Sigue siendo la forma más directa de colocar contenido en una cuadrícula — por ejemplo, una galería de miniaturas en filas y columnas.

<table>
  <tr>
    <td><img src="1.jpg" alt="Foto 1"></td>
    <td><img src="2.jpg" alt="Foto 2"></td>
  </tr>
  <tr>
    <td colspan="2"><img src="3.jpg" alt="Foto 3, panorámica"></td>
  </tr>
</table>

colspan hace que una celda ocupe varias columnas (útil para una imagen panorámica que rompe la cuadrícula); rowspan hace lo mismo en vertical.

¿Table o Flexbox/Grid?

Para maquetar el diseño general de una página moderna, lo normal es usar CSS (Flexbox o Grid — ver Fundamentos de CSS). Las tablas se reservan para datos que de verdad son tabulares: una cuadrícula de fotos, una hoja de resultados… Aun así, siguen siendo una herramienta perfectamente válida y rápida para una galería sencilla.

06

Formularios

Un formulario agrupa campos de entrada dentro de <form>. Cada campo necesita un <label> asociado (por accesibilidad y usabilidad: al pulsar la etiqueta, el foco salta al campo) y el type de <input> adecuado a cada dato.

<form>
  <label for="nombre">Nombre</label>
  <input type="text" id="nombre" name="nombre">

  <label for="clave">Contraseña</label>
  <input type="password" id="clave" name="clave">

  <label for="cumple">Fecha de nacimiento</label>
  <input type="date" id="cumple" name="cumple">

  <label for="pais">País</label>
  <select id="pais" name="pais">
    <option>España</option>
    <option>Francia</option>
  </select>

  <button type="submit">Enviar</button>
</form>
typePara qué sirve
textTexto libre de una línea.
passwordTexto oculto con puntos/asteriscos.
numberSolo números, con flechas de incremento.
dateSelector de fecha nativo del navegador.
emailTexto con validación básica de formato de email.
checkbox / radioCasillas de marcar / opciones excluyentes.

Elegir bien el type no es cosmético: en móvil cambia el teclado que aparece (numérico para number, con @ a mano para email…), y activa validaciones del propio navegador sin escribir JavaScript.

07

Buenas prácticas

  • Un único <h1> por página — es el título principal, no una talla de letra.
  • Todo <img> lleva alt, aunque sea descriptivo y corto.
  • Todo campo de formulario lleva su <label> — nunca solo un placeholder, que desaparece al escribir.
  • Rutas relativas (galeria.html) entre páginas del mismo sitio; rutas completas (https://...) solo para enlaces externos.
  • Valida el HTML de vez en cuando con el validador de la W3C — saca errores de etiquetas mal cerradas que el navegador perdona en silencio pero que dan problemas más adelante.

Con esto ya se puede montar el esqueleto de cualquier página. El siguiente paso es darle estilo: Fundamentos de CSS.
