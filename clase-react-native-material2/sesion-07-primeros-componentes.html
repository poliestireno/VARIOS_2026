Primeros componentes

La idea central de React: la interfaz no se dibuja a mano, se calcula a partir de los datos. Hoy escribes tus primeros componentes y aprendes a leerlos como lo hace React.

2 horas Sesión 7/26 JSX + componentes

Hasta ahora, para cambiar algo en una página has manipulado el DOM a mano: document.querySelector, .innerHTML, .appendChild. Funciona, pero a partir de cierto tamaño se vuelve imposible de seguir — demasiados sitios donde el HTML puede quedar desincronizado con los datos.

React cambia la pregunta. En vez de describir los pasos para modificar la pantalla, describes cómo debería verse para unos datos concretos, y es React quien decide qué tocar del DOM real. Todo lo de hoy es React normal, corriendo en el navegador, sin nada especial de móvil — ese salto llega más adelante, en el siguiente bloque. Por ahora, es HTML, JavaScript y una forma distinta de pensar la interfaz.

Qué vas a aprender

  • Qué es JSX y en qué se diferencia de verdad de escribir HTML.
  • Cómo crear un componente funcional y cómo le llegan datos desde fuera (props).
  • Cómo convertir un array de datos en una lista de componentes en pantalla, y por qué React exige la prop key.

JSX: por qué no es HTML

JSX se parece a HTML pero es JavaScript puro por debajo: cada etiqueta se convierte en una llamada a función que crea un objeto describiendo esa pieza de interfaz. Esto tiene consecuencias muy concretas al escribirlo.

function Saludo() {
  const nombre = "Ana";
  const esDeManana = new Date().getHours() < 12;

  return (
    <div className="saludo">
      <h2>Hola, {nombre}</h2>
      <p>{esDeManana ? "Buenos días" : "Buenas tardes"}</p>
    </div>
  );
}

Tres diferencias que se notan desde la primera línea: se usa className en lugar de class (porque class es palabra reservada en JavaScript), los atributos van en camelCase (onClick, no onclick), y cualquier {'{ }'} abre una ventana a JavaScript de verdad: puedes meter una variable, una operación, una llamada a función o un condicional corto — pero no una sentencia como un if completo, solo expresiones que devuelven un valor.

Un componente solo puede devolver una raíz

Si necesitas dos elementos hermanos, tienen que ir envueltos en un contenedor. Si no quieres añadir un div de más solo para eso, usa un fragmento vacío: <>...</>.

Componentes funcionales y props

Un componente en React es, literalmente, una función que devuelve JSX. Por convención empieza en mayúscula — así React distingue <div> (una etiqueta del navegador) de <TarjetaPerfil> (tu componente).

Las props son la forma en la que un componente recibe datos desde fuera: se escriben como atributos al usarlo, y le llegan a la función como un único objeto, que casi siempre se desestructura directamente en los parámetros. Igual que en la sesión de TypeScript, ese objeto se tipa con un type propio — por convención, con el mismo nombre del componente más Props:

type TarjetaPerfilProps = {
  nombre: string;
  rol: string;
};

function TarjetaPerfil({ nombre, rol }: TarjetaPerfilProps) {
  return (
    <div className="tarjeta">
      <h3>{nombre}</h3>
      <p>{rol}</p>
    </div>
  );
}

// se usa como si fuera una etiqueta más
<TarjetaPerfil nombre="Marta López" rol="Diseñadora UX" />

Escribirlo así tiene una ventaja inmediata frente a dejarlo sin tipar: si en algún sitio usas <TarjetaPerfil nombre="Ana" /> olvidando rol, el editor lo subraya en el momento — antes te habrías enterado con la pantalla mostrando undefined. Un detalle importante: las props son de solo lectura. TarjetaPerfil nunca debería reasignar nombre o rol — si necesita cambiar algo con el tiempo, eso es estado, y lo veremos en la próxima sesión.

Listas con .map() y la prop key

Casi nunca vas a escribir tres <TarjetaPerfil /> a mano: normalmente parten de un array de datos, y ese array se transforma en un array de elementos JSX con .map(), exactamente igual que transformarías cualquier otro array en JavaScript.

const personas = [
  { id: 1, nombre: "Marta López", rol: "Diseñadora UX" },
  { id: 2, nombre: "Carlos Ruiz", rol: "Desarrollador backend" },
  { id: 3, nombre: "Elena Gómez", rol: "Product manager" },
];

function ListaPerfiles() {
  return (
    <div className="lista">
      {personas.map((persona) => (
        <TarjetaPerfil
          key={persona.id}
          nombre={persona.nombre}
          rol={persona.rol}
        />
      ))}
    </div>
  );
}

React necesita key para saber qué elemento es cuál entre un render y el siguiente: sin ella, si la lista cambia de orden o pierde un elemento en el medio, React puede confundir dos tarjetas distintas y arrastrar estado o inputs al elemento equivocado. La key debe ser algo estable y único — un id de verdad, nunca algo que se recalcule cada vez (como Math.random()) ni, salvo listas totalmente estáticas, la posición en el array.

La idea que se queda de hoy

Un componente es una función que devuelve JSX. Los datos entran por props y fluyen de fuera hacia dentro. Una lista de datos se convierte en una lista de componentes con .map(), y cada uno necesita una key propia.

Práctica: fichas de equipo

Crea el componente TarjetaPerfil

Debe recibir por props al menos nombre y rol, y mostrarlos dentro de algo de estructura (un div con una clase te vale para darle estilo después).

2

Prepara un array de datos

Crea un array con 3 o 4 objetos {'{ id, nombre, rol }'}, con datos inventados de un equipo de trabajo.

3

En tu componente principal, recorre el array con .map() y devuelve una TarjetaPerfil por cada persona, sin olvidar la key.

Tantas tarjetas en pantalla como personas en el array, y ningún aviso amarillo en la consola sobre key.

4

Dale un mínimo de estilo

Con CSS normal (una clase .tarjeta te sirve): borde, espaciado interior, quizá una disposición en fila con display: flex y gap para que las tarjetas queden una junto a otra.

Reto extra

Añade una prop foto con una URL y muestra una <img> en la tarjeta (búscate avatares de prueba en https://i.pravatar.cc/150?img=N).

Añade una prop booleana destacado y, cuando sea true, muestra una estrella ⭐ junto al nombre usando un {'{destacado && ⭐}'} dentro del JSX.
