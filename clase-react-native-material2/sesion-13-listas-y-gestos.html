Listas y gestos

Dos capacidades que separan una app de juguete de una app de verdad: mostrar cientos de elementos sin que el móvil sufra, y responder al dedo del usuario cuando arrastra por la pantalla. Hoy tocamos FlatList y PanResponder.

Por qué no usar .map() dentro de un ScrollView

En React web, renderizar una lista con array.map() dentro de un contenedor con scroll funciona bien casi siempre, porque el navegador es muy eficiente recortando lo que no se ve. En React Native, un ScrollView con .map() hace algo mucho más caro: crea y monta en memoria los cientos de componentes de golpe, aunque el usuario solo vaya a ver 6 a la vez.

✗ Todo de golpe, cuesta caro 
<ScrollView>
  {contactos.map(c => (
    <Text key={c.id}>{c.nombre}</Text>
  ))}
</ScrollView>
✓ Solo lo que se ve, y un poco más 
<FlatList
  data={contactos}
  renderItem={({ item }) => <Text>{item.nombre}</Text>}
  keyExtractor={item => item.id}
/>

FlatList es una lista virtualizada: solo mantiene montados los elementos visibles en pantalla más un pequeño margen a cada lado. Cuando haces scroll, va montando lo nuevo y desmontando (o reciclando) lo que sale de vista, en vez de tener los 500 elementos vivos a la vez. Para 5 elementos no notarías diferencia; para 500, es la diferencia entre una app fluida y una que se congela.

La prop keyExtractor

keyExtractor le dice a FlatList cómo sacar un identificador único de cada elemento — cumple el mismo papel que la prop key que ya usabas en .map() en React web, solo que aquí es explícita y obligatoria para que la lista funcione bien.

const contactos = [
  { id: '1', nombre: 'Ana', telefono: '600 111 222' },
  { id: '2', nombre: 'Luis', telefono: '600 333 444' },
  // ...
];

<FlatList
  data={contactos}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => (
    <View style={styles.fila}>
      <Text style={styles.nombre}>{item.nombre}</Text>
      <Text style={styles.subtitulo}>{item.telefono}</Text>
    </View>
  )}
/>

Sin keyExtractor, FlatList intenta usar el índice de cada elemento como identificador — funciona a medias, pero en cuanto la lista se reordena o filtra, React puede confundir un elemento con otro y reutilizar mal las filas. Con datos que tienen un id propio, dáselo siempre.

PanResponder: seguir un dedo por la pantalla

Los mini-juegos que ya habéis construido —Arcanoid y Pang— mueven la pala arrastrando el dedo por la pantalla. Ese arrastre se captura con PanResponder, la API de bajo nivel de React Native para gestos táctiles. Este es el código real que usa la pala:

const panResponder = useRef(
  PanResponder.create({
    // Solo capturamos el gesto mientras se juega, para no bloquear los botones.
    onStartShouldSetPanResponder: () => juego.estado === 'jugando',
    onMoveShouldSetPanResponder: () => juego.estado === 'jugando',
    onPanResponderMove: (evento) => {
      const x = evento.nativeEvent.locationX;
      juego.jugadorX = Math.max(0, Math.min(anchoJuego - ANCHO_JUGADOR, x - ANCHO_JUGADOR / 2));
      redibujar();
    },
  })
).current;

Vamos por partes:

  • PanResponder.create({ ... }) crea el manejador de gestos. Se envuelve en useRef(...).current para que sea el mismo objeto durante toda la vida del componente — no tiene sentido recrearlo en cada render.
  • onStartShouldSetPanResponder y onMoveShouldSetPanResponder son las preguntas que React Native hace antes de “entregarte” el gesto: “¿quieres capturar este toque que empieza?” y “¿quieres capturar este movimiento?”. Devuelven true o false. Aquí ambas comprueban juego.estado === 'jugando': si el gesto se capturara siempre, arrastrar el dedo sobre un botón dibujado encima del área de juego (como “Pausa” o “Reiniciar”) quedaría bloqueado, porque el PanResponder se habría quedado con el toque antes de que le llegara al botón. Condicionar la captura al estado del juego evita justo eso.
  • onPanResponderMove se dispara en cada movimiento, una vez que el gesto ya fue capturado. evento.nativeEvent.locationX es la posición horizontal del dedo relativa al elemento tocado (no a la pantalla entera) — el dato que necesitamos para saber dónde mover la pala.
  • El patrón Math.max(0, Math.min(límite, valor)) es un “clamp”: obliga a valor a quedarse entre 0 y límite. Aquí evita que la pala se salga del área de juego por la izquierda (nunca baja de 0) o por la derecha (nunca supera anchoJuego - ANCHO_JUGADOR). Restar ANCHO_JUGADOR / 2 centra la pala respecto al dedo, en vez de dejar el borde izquierdo pegado a él.

Práctica

1

Lista con FlatList

Crea un array con al menos 15 elementos (contactos, productos, canciones… lo que prefieras), cada uno con un id, un nombre y un subtítulo. Muéstralo con FlatList, con su keyExtractor correspondiente, y da estilo a cada fila con StyleSheet (por ejemplo, nombre en negrita arriba, subtítulo atenuado debajo, con un borde inferior fino separando filas).

Pista: la prop ItemSeparatorComponent te deja añadir una línea divisoria entre filas sin tener que meterla dentro de cada renderItem.

2

Una caja que se arrastra

En una segunda pantalla (o debajo de la lista), construye una “pista” horizontal —una View ancha y baja— con un cuadrado de color dentro que el usuario pueda arrastrar a izquierda y derecha con el dedo, sin salirse de los bordes de la pista. Reutiliza el patrón de PanResponder de arriba, simplificado: no necesitas condición de estado de juego, así que onStartShouldSetPanResponder y onMoveShouldSetPanResponder pueden devolver true directamente. Guarda la posición X del cuadrado en un useState, y en onPanResponderMove actualízala con el mismo patrón de Math.max/Math.min para no salirte del ancho de la pista.

Reto extra: en la lista de la pista, añade un número que muestre el porcentaje de recorrido del cuadrado (0% pegado a la izquierda, 100% pegado a la derecha), calculado a partir de su posición X y el ancho de la pista.
