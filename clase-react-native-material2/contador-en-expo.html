Tu primera app con Expo: un contador

De un portátil vacío a un botón que suma, funcionando en tu propio móvil. Sin Mac, sin Android Studio, sin Xcode.

React Native + Expo SDK 54 TypeScript VS Code Android & iOS ~20 min

Antes de empezar

  • Node.js instalado en tu portátil (cualquier versión reciente sirve). Lo compruebas con node -v en una terminal.
  • Visual Studio Code instalado — es el editor que vamos a usar de principio a fin, terminal incluida.
  • Tu móvil (Android o iPhone), con la app Expo Go instalada desde Play Store o App Store.
  • Portátil y móvil conectados a la misma red wifi.

Extensiones de VS Code

  • Ninguna es obligatoria: el proyecto funciona con un VS Code recién instalado, sin extra alguno.
  • ES7+ React/Redux/React-Native Snippets (dsznajder) — atajos como rnfes para generar un componente entero en dos teclas. La más rentable para una clase.
  • Prettier – Code formatter — ordena el código solo al guardar. Útil para que el código de todos los alumnos tenga el mismo formato de un vistazo.
  • Expo Tools (Expo) — resalta la sintaxis de app.json/app.config.js y permite lanzar comandos de Expo desde VS Code.

Se instalan igual todas: icono de piezas de puzle en la barra lateral izquierda (Ctrl+Shift+X), buscas el nombre, “Install”. Si activas Prettier, actívale también “Format on Save” en Settings para que actúe solo.

Qué vas a aprender

  • Cómo se arranca y se prueba una app de React Native en un móvil real, sin compilar nada nativo.
  • Los componentes básicos: View, Text, Pressable.
  • Cómo guardar y mostrar un valor que cambia con useState.

Los pasos

1

Abre VS Code y su terminal integrada

No hace falta salir de VS Code en ningún momento: tiene una terminal propia. Ábrela con Ctrl + ` (comilla invertida), o desde el menú Terminal → Nueva terminal.

2

Crea el proyecto

En esa terminal, sitúate en la carpeta donde quieras guardar tus proyectos y ejecuta:

$ npx create-expo-app mi-primera-app
$ cd mi-primera-app

Sin ningún --template, obtienes la plantilla oficial por defecto: un proyecto ya en TypeScript, con la navegación resuelta por Expo Router (cada archivo dentro de app/ es una pantalla) y un par de pestañas de ejemplo ya montadas.

Tarda entre 30 segundos y un par de minutos, según tu conexión.

Deberías ver esto

Una lista de paquetes instalándose y, al final, algo como ✅ Your project is ready!. Si te pregunta por un gestor de paquetes, elige npm (la opción por defecto, tecla Enter).

2.1

Limpia la plantilla de ejemplo

La plantilla por defecto trae dos pestañas de muestra (“Home” y “Explore”) con componentes temáticos que no necesitamos para esta guía. Expo incluye un script que las aparta automáticamente:

$ npm run reset-project

Mueve todo el ejemplo a una carpeta app-example/ (que puedes borrar cuando quieras) y deja app/ con solo dos archivos: _layout.tsx y index.tsx. Contesta “y” si te pregunta si quieres continuar.

3

Abre la carpeta del proyecto en VS Code

$ code .

Si code . no hace nada, usa el menú File → Open Folder… y selecciona la carpeta mi-primera-app. Verás sus archivos en el panel de la izquierda (el Explorer).

La primera vez, VS Code puede preguntarte “Do you trust the authors of this folder?” — dale a Yes, I trust the authors, es tu propio proyecto.

4

Arranca el servidor

$ npm start

En la terminal integrada aparecerá un código QR. Déjalo abierto: es el servidor de desarrollo, tiene que seguir corriendo mientras trabajas.

Deberías ver esto

Un QR grande, y debajo un menú de texto con opciones como Press a │ open Android, Press w │ open web. No pulses ninguna letra todavía — vamos a usar el QR con el móvil.

5

Ábrelo en el móvil

Android: abre la app Expo Go, pulsa el botón “Scan QR code” y apunta a la pantalla.

iPhone: abre la app Cámara normal (no Expo Go) y apunta al QR; te saldrá un aviso arriba para abrirlo en Expo Go.

La primera vez tarda un poco más: el móvil está descargando el bundle de JS de tu app.

Deberías ver esto

Una pantalla blanca con el texto “Edit app/index.tsx to edit this screen.” centrado. Si ves eso, todo está conectado correctamente.

Si el móvil dice “Project is incompatible with this version of Expo Go”

Expo Go de las tiendas suele ir un paso por detrás de la última versión de Expo. Baja el proyecto a la versión que sí soporta la app de la tienda:

$ npx expo install expo@^54.0.0
$ npx expo install --fix

Para y vuelve a lanzar npm start, y escanea otra vez.

6

Abre app/index.tsx

En el Explorer de la izquierda, despliega la carpeta app y haz clic en index.tsx. Es el único archivo que necesitas tocar para esta guía: es la pantalla que Expo Router muestra en la ruta raíz (“/”) de la app. Ya trae un ejemplo mínimo: un fondo blanco con un texto centrado. Ese será tu punto de partida.

¿No ves index.tsx directamente dentro de app/, sino una carpeta (tabs) y varios archivos más? Es señal de que falta el paso 2.1: cierra el servidor con Ctrl+C y ejecuta npm run reset-project.

7

Escribe el contador

Vamos a construirlo por partes dentro de app/index.tsx, para que veas qué hace cada trozo antes de juntarlo todo. Aprovecha el autocompletado de VS Code mientras escribes — al ser TypeScript, te avisará en rojo si te falta un tipo o te equivocas de nombre de propiedad.

7.1

Importa lo que necesitas

Borra el contenido de app/index.tsx y empieza por estas tres líneas:

import { useState } from 'react';
import { StatusBar } from 'expo-status-bar';
import { StyleSheet, Text, View, Pressable } from 'react-native';

react te da useState; react-native te da los componentes visuales: View (un contenedor, como un div), Text (todo texto tiene que ir dentro de uno) y Pressable (un botón táctil).

7.2

Guarda el número que cambia

Debajo, crea el componente con su estado:

export default function Index() {
  const [contador, setContador] = useState<number>(0);

  return (
    <View style={styles.container}>
    </View>
  );
}

useState<number>(0) arranca en cero y le dice a TypeScript que contador siempre va a ser un número — si más adelante intentas guardarle un texto por error, el editor te lo marcará antes de llegar al móvil. Te da dos cosas: contador (el valor actual, solo lectura) y setContador (la única forma permitida de cambiarlo).

7.3

Dibuja la pantalla

Rellena ese View vacío:

    <View style={styles.container}>
      <Text style={styles.titulo}>¡Hola, React Native!</Text>
      <Text style={styles.contador}>{contador}</Text>
      <Pressable style={styles.boton} onPress={() => setContador(contador + 1)}>
        <Text style={styles.textoBoton}>Sumar 1</Text>
      </Pressable>
      <StatusBar style="auto" />
    </View>

onPress se ejecuta cada vez que tocas el Pressable. Al llamar a setContador, React vuelve a dibujar la pantalla solo con el número nuevo — tú no tocas el texto a mano en ningún sitio.

7.4

Dale estilo

Y cierra el archivo con los estilos, fuera del componente:

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    alignItems: 'center',
    justifyContent: 'center',
    gap: 16,
  },
  titulo: { fontSize: 22, fontWeight: 'bold' },
  contador: { fontSize: 48 },
  boton: {
    backgroundColor: '#2563eb',
    paddingVertical: 12,
    paddingHorizontal: 24,
    borderRadius: 8,
  },
  textoBoton: { color: '#fff', fontSize: 18 },
});

StyleSheet.create es un objeto de JavaScript, no CSS: los nombres van en camelCase (backgroundColor, no background-color) y no hay herencia entre elementos.

8

Guarda y mira el móvil

Guarda con Ctrl+S. No hace falta volver a escanear nada: en cuanto guardas, el móvil se actualiza solo (esto se llama Fast Refresh).

Deberías ver esto

El texto “¡Hola, React Native!”, un 0 grande debajo, y un botón azul “Sumar 1”. Tócalo: el número sube a 1, 2, 3… Si no cambia nada, revisa que guardaste el archivo y que el servidor sigue corriendo.

9

Para cuando termines

En el móvil no hay que hacer nada especial, puedes cerrar la app sin más. En la terminal integrada de VS Code, pulsa Ctrl+C para apagar el servidor — nunca Ctrl+Z, que solo lo deja colgado en segundo plano ocupando el puerto.

Si algo falla

Dentro de app/ veo una carpeta (tabs), explore.tsx y un montón de componentes que no hemos escrito

Es la plantilla de ejemplo de Expo Router, que trae dos pestañas montadas por defecto. Se te olvidó el paso 2.1: para el servidor con Ctrl+C, ejecuta npm run reset-project y contesta “y”. Al terminar, app/ se queda solo con _layout.tsx e index.tsx.

El móvil dejó de recibir cambios a mitad de clase

Casi siempre es porque el móvil cambió de red (por ejemplo, pasó a datos móviles). Portátil y móvil tienen que estar en la misma wifi. Si la wifi del centro aísla los dispositivos entre sí, arranca con npx expo start --tunnel en su lugar.

¿Hay que reiniciar todo cada vez que cambio código?

No. Mientras el servidor siga encendido, cada guardado se refleja solo en el móvil. Solo hace falta reiniciar si instalas una librería nueva o tocas la configuración del proyecto.

Aparecen “vulnerabilities” al instalar

Son avisos sobre herramientas internas de desarrollo, no sobre tu app ni sobre lo que corre en el móvil. Para una clase, se pueden ignorar sin problema — y sobre todo, no ejecutéis npm audit fix --force, puede cambiaros la versión de Expo sin avisar.
