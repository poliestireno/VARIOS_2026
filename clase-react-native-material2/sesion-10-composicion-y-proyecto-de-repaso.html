Composición y proyecto de repaso

Cierras el bloque de React combinando lo de las tres sesiones anteriores — componentes, props, estado, efectos, formularios — en una app pequeña pero completa, hecha de varias piezas que hablan entre sí.

2 horas Sesión 10/26 Composición de componentes

Ninguna app de verdad vive en un único componente gigante. Se construye combinando componentes pequeños, cada uno responsable de una cosa, que se comunican entre sí de una forma muy concreta: los datos bajan por props, y las acciones (lo que ocurre cuando algo pasa) suben también por props, pero en forma de funciones. A eso se le llama composición, y es lo que hace que React escale de un contador a una aplicación entera. Seguimos en el navegador, con React normal — hoy cerramos este bloque.

Qué vas a aprender

  • Cómo pasar props a través de varios niveles de componentes, incluyendo funciones que un componente hijo usa para avisar a su padre.
  • Cómo organizar componentes en archivos separados con import / export.
  • Cuándo tiene sentido partir un componente en dos (y cuándo no merece la pena).

Props a través de varios niveles

Cuando un componente hijo necesita avisar a su padre de que algo ha pasado (un clic, un envío de formulario), el padre le pasa una función por props, y el hijo simplemente la llama en el momento adecuado. El hijo no sabe ni le importa qué hace esa función por dentro — solo la ejecuta.

function App() {
  const usuario = { nombre: "Marta", puntos: 120 };
  return <Perfil usuario={usuario} />;
}

function Perfil({ usuario }) {
  return (
    <div>
      <Avatar nombre={usuario.nombre} />
      <Puntuacion puntos={usuario.puntos} />
    </div>
  );
}

function Avatar({ nombre }) {
  return <p>{nombre.charAt(0)}</p>;
}

function Puntuacion({ puntos }) {
  return <p>{puntos} pts</p>;
}

App nunca le pasa nada directamente a Avatar ni a Puntuacion: Perfil hace de intermediario, cogiendo el objeto usuario y repartiendo trozos de él. Ahora, el mismo patrón pero con una función en vez de un dato:

function App() {
  function saludar(nombre) {
    alert(`Hola, ${nombre}`);
  }
  return <Perfil onSaludar={saludar} />;
}

function Perfil({ onSaludar }) {
  return <button onClick={() => onSaludar("Marta")}>Saludar</button>;
}

Es la misma idea que ya usaste en la sesión 8 al pasar onAlternar o onEliminar a cada tarea de la lista: el dato vive arriba, en el componente que tiene el estado, y las funciones bajan para que los componentes de abajo puedan pedir cambios sin tener acceso directo a ese estado.

Un archivo por componente

Mientras un componente es pequeño, tenerlo todo en App.tsx es cómodo. En cuanto un proyecto crece, conviene separar cada componente (o cada grupo de componentes muy relacionados) en su propio archivo, y conectar todo con import / export.

// Avatar.tsx
export function Avatar({ nombre }) {
  return <p className="avatar">{nombre.charAt(0)}</p>;
}

// Perfil.tsx
import { Avatar } from "./Avatar";

export function Perfil({ usuario }) {
  return (
    <div className="perfil">
      <Avatar nombre={usuario.nombre} />
    </div>
  );
}

Cada archivo exporta su componente (con export, o export default si es el único que exporta ese archivo) y lo importa quien lo necesite. A cambio de un poco más de navegación entre archivos, ganas que cada uno se entienda solo, sin tener que leer 300 líneas para encontrar un botón.

¿Cuándo merece la pena partir un componente en dos?

Buenas señales: el componente hace más de una cosa claramente distinta, una parte de él se repite en otro sitio, o tiene tanto JSX que cuesta encontrar la lógica entre medio. Mala señal para partirlo: hacerlo “porque sí” cuando todo cabe cómodo y no se reutiliza en ningún otro sitio — la composición ayuda hasta que empieza a ser más indirección que claridad.

El patrón que vas a usar en el proyecto

El proyecto de hoy sigue un reparto de responsabilidades muy común: un componente “de arriba” guarda el estado y las funciones que lo modifican, y componentes “de abajo” solo reciben datos y funciones por props, sin estado propio relevante para la lógica de negocio.

La idea que se queda de hoy

Los datos bajan por props, las acciones suben como funciones pasadas por props. El estado vive lo más arriba posible, cerca de donde varios componentes lo necesitan compartir.

Práctica: lista de la compra

El proyecto integrador del bloque: añadir productos, marcarlos como comprados, eliminarlos, y ver un contador de progreso. Como mínimo, tres componentes que se comuniquen por props.

1

App: el estado y el contador

El componente principal guarda el array de productos en estado, y calcula cuántos están comprados. Cada producto puede ser {'{ id, nombre, comprado }'}.

type Producto = { id: number; nombre: string; comprado: boolean };

function App() {
  const [productos, setProductos] = useState<Producto[]>([]);

  function anadirProducto(nombre: string) {
    const nuevo: Producto = { id: Date.now(), nombre, comprado: false };
    setProductos([...productos, nuevo]);
  }

  function alternarComprado(id: number) {
    setProductos(
      productos.map((p) => (p.id === id ? { ...p, comprado: !p.comprado } : p))
    );
  }

  function eliminarProducto(id: number) {
    setProductos(productos.filter((p) => p.id !== id));
  }

  const comprados = productos.filter((p) => p.comprado).length;

  return (
    <div className="app">
      <h1>Lista de la compra</h1>
      <p>{comprados} de {productos.length} comprados</p>
      <FormularioProducto onAnadir={anadirProducto} />
      <ListaProductos
        productos={productos}
        onAlternar={alternarComprado}
        onEliminar={eliminarProducto}
      />
    </div>
  );
}
2

FormularioProducto: solo pide el nombre

Tiene su propio estado local para el texto del input (es un detalle interno suyo, no le importa a App), y cuando se envía, llama a onAnadir con el nombre escrito.

type FormularioProductoProps = { onAnadir: (nombre: string) => void };

function FormularioProducto({ onAnadir }: FormularioProductoProps) {
  const [texto, setTexto] = useState("");

  function manejarEnvio(e: React.FormEvent) {
    e.preventDefault();
    if (texto.trim() === "") return;
    onAnadir(texto);
    setTexto("");
  }

  return (
    <form onSubmit={manejarEnvio}>
      <input
        value={texto}
        onChange={(e) => setTexto(e.target.value)}
        placeholder="Nuevo producto"
      />
      <button type="submit">Añadir</button>
    </form>
  );
}
3

ListaProductos y Producto: recorrer y delegar

ListaProductos solo recorre el array con .map() y reparte props a cada Producto; no tiene lógica propia. Producto muestra un elemento y llama a las funciones que recibe cuando hace falta.

type ListaProductosProps = {
  productos: Producto[];
  onAlternar: (id: number) => void;
  onEliminar: (id: number) => void;
};

function ListaProductos({ productos, onAlternar, onEliminar }: ListaProductosProps) {
  return (
    <ul>
      {productos.map((p) => (
        <Producto
          key={p.id}
          producto={p}
          onAlternar={onAlternar}
          onEliminar={onEliminar}
        />
      ))}
    </ul>
  );
}

type ProductoProps = {
  producto: Producto;
  onAlternar: (id: number) => void;
  onEliminar: (id: number) => void;
};

function Producto({ producto, onAlternar, onEliminar }: ProductoProps) {
  return (
    <li>
      <span
        onClick={() => onAlternar(producto.id)}
        style={{
          textDecoration: producto.comprado ? "line-through" : "none",
        }}
      >
        {producto.nombre}
      </span>
      <button onClick={() => onEliminar(producto.id)}>
        Eliminar
      </button>
    </li>
  );
}
Deberías ver esto

Puedes añadir productos, marcarlos como comprados haciendo clic en su nombre, eliminarlos, y el contador de arriba (“X de Y comprados”) se actualiza solo en cada acción, sin que tú lo recalcules a mano en ningún sitio aparte de App.

4

Separa en archivos

Con los cuatro componentes funcionando en un solo archivo, muévelos a FormularioProducto.tsx, ListaProductos.tsx y Producto.tsx, cada uno con su export, e impórtalos donde haga falta. App se queda como el archivo que los conecta a todos.

Reto extra

Añade un botón “Vaciar comprados” en App que elimine de golpe todos los productos con comprado: true, usando .filter().

Guarda la lista en localStorage con useEffect cada vez que cambie productos, y recupérala al cargar la página, para que sobreviva a un refresco del navegador.
