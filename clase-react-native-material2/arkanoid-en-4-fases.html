Guía de clase · práctica de la Sesión 18

Arkanoid en 4 fases

El “rompebloques” de toda la vida, construido paso a paso: primero el escenario quieto, luego la paleta, luego la física de la pelota, y por último los bloques de verdad. Cada fase es un archivo independiente y funcionando — nunca te quedas con código a medias.

React Native + Expo TypeScript PanResponder useRef + bucle de juego ~45 min
← Volver a la Sesión 18

Antes de empezar

  • Node.js y VS Code instalados, y un proyecto de Expo funcionando en tu móvil. Si todavía no tienes ninguno, sigue primero la guía “Contador en Expo” — los pasos de creación son idénticos, solo cambia el nombre del proyecto.
  • Haber visto useState (Sesión 8), useEffect (Sesión 9) y, sobre todo, tener fresca la Sesión 18: aquí vamos a construir en vivo el “Patrón A” (bucle en tiempo real con useRef) que esa sesión solo explica en teoría.

Qué vas a construir

Cuatro pantallas, cada una un poco más completa que la anterior. Ninguna se queda a medias: en cualquier fase tienes algo que se ve y se toca.

  • Fase 1 · Escenario estático — la paleta, la pelota y los bloques colocados en su sitio, sin moverse. Solo layout con View y posición absoluta.
  • Fase 2 · Mover la paleta — arrastras el dedo (o el ratón, en la versión web) y la paleta te sigue, con PanResponder y un useState normal.
  • Fase 3 · La pelota rebota sola — la pelota se mueve 60 veces por segundo y rebota en paredes y en la paleta. Aquí pasamos del useState al useRef + bucle de la Sesión 18, porque ya no nos lo podemos permitir.
  • Fase 4 · Romper bloques y ganar — los bloques pasan a formar parte del estado del juego: la pelota choca con ellos, los rompe, y ganas si los destruyes todos.

Preparación: crea el proyecto

1

Crea un proyecto de Expo nuevo

En la terminal integrada de VS Code:

$ npx create-expo-app arkanoid
$ cd arkanoid
$ npm run reset-project

Contesta “n” si reset-project te pregunta si quieres mover los archivos de ejemplo a /example en vez de borrarlos — para este proyecto no los necesitamos. Al terminar, te quedan solo src/app/_layout.tsx y src/app/index.tsx.

2

Crea los 4 archivos de las fases

Dentro de src/app/, crea cuatro archivos vacíos: fase1.tsx, fase2.tsx, fase3.tsx y fase4.tsx. Con Expo Router, el simple hecho de crear el archivo ya le da una ruta — fase1.tsx será accesible en /fase1, sin tocar ninguna configuración.

Convierte index.tsx en un menú

Fase 1

Escenario estático

Objetivo: colocar la paleta, la pelota y los bloques en su sitio. Nada se mueve todavía — el reto es puramente de layout.

1

El área de juego: una caja con posición relativa

Todo el juego vive dentro de una View de tamaño fijo (anchoJuego × altoJuego) con position: 'relative'. Es la clave de todo lo que sigue: cualquier hijo con position: 'absolute' se coloca dentro de esa caja, con left/top midiendo desde su esquina superior izquierda — no desde la pantalla entera.

extracto
areaJuego: {
  backgroundColor: '#0a0a23',
  position: 'relative',
  overflow: 'hidden',  // lo que se salga de la caja no se ve
  borderRadius: 8,
},
2

Los bloques: una cuadrícula calculada, no escrita a mano

En vez de escribir 20 View con coordenadas a mano, generamos su posición con dos bucles for anidados (fila × columna) y las guardamos en un array normal. MARGEN_BLOQUES se calcula a partir del resto de constantes para que la cuadrícula quede centrada, sin tener que reajustarlo a mano si cambias el número de columnas.

extracto
const MARGEN_BLOQUES =
  (anchoJuego - (BLOQUES_POR_FILA * ANCHO_BLOQUE + (BLOQUES_POR_FILA - 1) * ESPACIO_BLOQUES)) / 2;

const bloques: { x: number; y: number }[] = [];
for (let fila = 0; fila < FILAS_BLOQUES; fila++) {
  for (let columna = 0; columna < BLOQUES_POR_FILA; columna++) {
    bloques.push({
      x: MARGEN_BLOQUES + columna * (ANCHO_BLOQUE + ESPACIO_BLOQUES),
      y: Y_INICIAL_BLOQUES + fila * (ALTO_BLOQUE + ESPACIO_BLOQUES),
    });
  }
}

Luego, en el JSX, un bloques.map(...) convierte ese array en una View por bloque — el mismo patrón que ya usaste con FlatList y con .map() en React web, aplicado aquí a rectángulos en vez de a filas de una lista.

const altoJuego = 480;

const BLOQUES_POR_FILA = 5;
const ANCHO_BLOQUE = 50;

Fase 2

Mover la paleta

Objetivo: arrastrar el dedo dentro del área de juego mueve la paleta. La pelota y los bloques siguen decorativos.

1

PanResponder: seguir un dedo por la pantalla

Ya lo viste en la Sesión 13: PanResponder.create({'{ ... }'}) crea el manejador de gestos, envuelto en useRef(...).current para que sea siempre el mismo objeto. Aquí no hace falta condición de estado de juego todavía (eso llega en la Fase 3): ambas preguntas devuelven true directamente.

extracto
const [jugadorX, setJugadorX] = useState((anchoJuego - ANCHO_JUGADOR) / 2);

const panResponder = useRef(
  PanResponder.create({
    onStartShouldSetPanResponder: () => true,
    onMoveShouldSetPanResponder: () => true,
    onPanResponderMove: (evento) => {
      const x = evento.nativeEvent.locationX;
      setJugadorX(Math.max(0, Math.min(anchoJuego - ANCHO_JUGADOR, x - ANCHO_JUGADOR / 2)));
    },
  })
).current;

evento.nativeEvent.locationX es la posición horizontal del dedo relativa al área de juego (gracias a que se lo pasamos con {'{...panResponder.panHandlers}'} a esa misma View). El “clamp” Math.max(0, Math.min(límite, valor)) evita que la paleta se salga por los lados, y restar la mitad de su ancho la centra respecto al dedo en vez de pegar su borde izquierdo a él.

2

Conecta el gesto al área de juego

extracto
<View
  style={[styles.areaJuego, { width: anchoJuego, height: altoJuego }]}
  {...panResponder.panHandlers}
>
  {/* bloques, pelota y paleta (con left: jugadorX) */}
</View>

panResponder.panHandlers es un objeto con varias props (onStartShouldSetResponder, onResponderMove…) que React Native usa por debajo para conectar el sistema de gestos a este elemento en concreto. Al esparcirlo con {'{...}'}, esta View pasa a “escuchar” el dedo.

  // normal: nada se mueve solo 60 veces por segundo, así que no hace
  // falta el patrón de useRef + bucle que veremos en la Fase 3.

  // de juego. Se crea una sola vez (useRef) porque no tiene sentido

      onMoveShouldSetPanResponder: () => true,

Fase 3

La pelota rebota sola

Objetivo: la pelota se mueve constantemente y rebota en paredes y en la paleta. Pierdes si se cae. Los bloques siguen siendo decorativos.

Aquí es donde entra el Patrón A de la Sesión 18

Hasta ahora, cada cambio ha sido un useState disparado por el usuario: tocar, arrastrar. Pero una pelota que se mueve sola, 60 veces por segundo, no se puede modelar así — cada setState agenda un render completo, y a esa frecuencia satura la app en segundos. La solución es la de la Sesión 18: el estado real vive en un useRef (que no provoca render al mutarlo), y un useState aparte se usa solo como “disparador” para pedir un repintado una vez por frame.

1

Todo el estado, en un solo objeto juego

Antes de tocar el componente, definimos qué forma tiene el estado y cómo se crea desde cero:

extracto
type EstadoJuego = 'jugando' | 'perdido';

type Juego = {
  estado: EstadoJuego;
  jugadorX: number;
  pelota: { x: number; y: number; vx: number; vy: number };
};

function crearEstadoInicial(): Juego {
  return {
    estado: 'jugando',
    jugadorX: (anchoJuego - ANCHO_JUGADOR) / 2,
    pelota: { x: anchoJuego / 2, y: altoJuego / 2, vx: VELOCIDAD_INICIAL_PELOTA, vy: VELOCIDAD_INICIAL_PELOTA },
  };
}

vx/vy son la velocidad de la pelota en cada eje: cuántos píxeles avanza por “tick” del bucle. Invertir su signo (vy = -vy) es toda la física que necesita un rebote “muy sencillo”.

2

La física, en una función aparte que muta el objeto

actualizarFisica no devuelve nada: recibe juego y lo modifica directamente (pelota.x += pelota.vx). Es exactamente el estilo que describe la Sesión 18 para este patrón.

extracto
function actualizarFisica(juego: Juego) {
  if (juego.estado !== 'jugando') return;

  const pelota = juego.pelota;
  pelota.x += pelota.vx;
  pelota.y += pelota.vy;

  // Paredes izquierda/derecha
  if (pelota.x <= 0 || pelota.x >= anchoJuego - TAMANO_PELOTA) pelota.vx = -pelota.vx;

  // Techo
  if (pelota.y <= 0) pelota.vy = -pelota.vy;

  // Paleta: solo si la pelota va bajando y coincide en X e Y
  const tocaAlturaPaleta = pelota.y + TAMANO_PELOTA >= Y_JUGADOR && pelota.y <= Y_JUGADOR + ALTO_JUGADOR;
  const tocaAnchoPaleta = pelota.x + TAMANO_PELOTA >= juego.jugadorX && pelota.x <= juego.jugadorX + ANCHO_JUGADOR;
  if (pelota.vy > 0 && tocaAlturaPaleta && tocaAnchoPaleta) pelota.vy = -pelota.vy;

  // Se acabó: la pelota pasó de largo
  if (pelota.y > altoJuego) juego.estado = 'perdido';
}

La comprobación pelota.vy > 0 antes del rebote en la paleta evita un bug clásico: sin ella, si la pelota queda pegada a la paleta un par de frames, podría rebotar varias veces seguidas en el mismo golpe.

3

El componente: useRef + setInterval + redibujar

extracto
const juego = useRef(crearEstadoInicial()).current;

const [, setTick] = useState(0);
const redibujar = () => setTick((n) => n + 1);

useEffect(() => {
  const id = setInterval(() => {
    actualizarFisica(juego);
    redibujar();
  }, 16);
  return () => clearInterval(id);
}, []);

16 milisegundos por frame es, aproximadamente, 60 frames por segundo (1000/60 ≈ 16.67). El useEffect con array de dependencias vacío ([]) arranca el intervalo una sola vez, cuando el componente se monta, y lo limpia con clearInterval si el componente desaparece — exactamente igual que ya viste con setInterval en el mini Space Invaders y en el Adivina el número.

El PanResponder cambia respecto a la Fase 2: ya no existe setJugadorX, así que muta juego.jugadorX directamente y llama a redibujar() a mano. Las dos condiciones onStartShouldSetPanResponder/onMoveShouldSetPanResponder ahora comprueban juego.estado === 'jugando', para no capturar el gesto cuando ya ha aparecido el botón de “Reintentar” encima.

// Los bloques siguen siendo decorativos: todavía no chocan (Fase 4).

type Juego = {
  estado: EstadoJuego;
  jugadorX: number; // posición X de la paleta
  pelota: { x: number; y: number; vx: number; vy: number };
};

function crearEstadoInicial(): Juego {
  return {
    estado: 'jugando',
    jugadorX: (anchoJuego - ANCHO_JUGADOR) / 2,
    pelota: {
      x: anchoJuego / 2,
      y: altoJuego / 2,

      vy: VELOCIDAD_INICIAL_PELOTA,

// Mueve la pelota un paso y resuelve los rebotes. MUTA "juego" directamente
// (no devuelve nada): es el propio objeto que vive en el useRef del componente.
function actualizarFisica(juego: Juego) {
  if (juego.estado !== 'jugando') return;

  const pelota = juego.pelota;
  pelota.x += pelota.vx;
  pelota.y += pelota.vy;

  // Rebote en la pared izquierda o derecha: invertimos la velocidad horizontal.
  if (pelota.x <= 0 || pelota.x >= anchoJuego - TAMANO_PELOTA) {
    pelota.vx = -pelota.vx;
  }

  // Rebote en el techo: invertimos la velocidad vertical.
  if (pelota.y <= 0) {
    pelota.vy = -pelota.vy;
  }

  // Rebote en la paleta: solo cuenta si la pelota está bajando (vy > 0,
  // para no "atraparla" rebotando varias veces seguidas) y coincide con
  // la paleta tanto en su altura como en su rango horizontal.
  const tocaAlturaPaleta = pelota.y + TAMANO_PELOTA >= Y_JUGADOR && pelota.y <= Y_JUGADOR + ALTO_JUGADOR;
  const tocaAnchoPaleta = pelota.x + TAMANO_PELOTA >= juego.jugadorX && pelota.x <= juego.jugadorX + ANCHO_JUGADOR;
  if (pelota.vy > 0 && tocaAlturaPaleta && tocaAnchoPaleta) {
    pelota.vy = -pelota.vy;
  }

  // Si la pelota pasó de largo la paleta, se acabó la partida.
  if (pelota.y > altoJuego) {
    juego.estado = 'perdido';
  }
}

Fase 4

Romper bloques y ganar

Objetivo: los bloques dejan de ser decoración. La pelota comprueba si choca con alguno, lo rompe, y ganas al destruirlos todos.

1

Los bloques entran en el estado del juego

Cada bloque pasa de ser {'{ x, y }'} a tener también un vivo: boolean, y el array completo vive dentro de Juego, no fuera:

Es la misma comprobación de rectángulos que ya usaste para las balas contra los enemigos del mini Space Invaders: si los dos rangos (en X y en Y) se solapan, hay choque. Se añade dentro de actualizarFisica, después de resolver paredes y paleta:

El break es intencionado: para un Arkanoid “muy sencillo” basta con resolver un bloque por frame, aunque en teoría la pelota pudiera tocar dos a la vez. .every(...) devuelve true solo si ningún bloque sigue vivo — ahí se dispara la victoria.

3

import { useEffect, useRef, useState } from 'react';
import { PanResponder, Pressable, StyleSheet, Text, View } from 'react-native';

// ---------------------------------------------------------------------
// FASE 4: los bloques dejan de ser decoración. Ahora forman parte del
// estado del juego (cada uno con su "vivo"), la pelota comprueba si
// choca contra alguno, y se gana la partida al destruirlos todos.
// ---------------------------------------------------------------------

const anchoJuego = 300;
const altoJuego = 480;

const ANCHO_JUGADOR = 70;
const ALTO_JUGADOR = 14;
const Y_JUGADOR = altoJuego - 40;

const TAMANO_PELOTA = 14;
const VELOCIDAD_INICIAL_PELOTA = 4;

const FILAS_BLOQUES = 4;
const BLOQUES_POR_FILA = 5;
const ANCHO_BLOQUE = 50;
const ALTO_BLOQUE = 18;
const ESPACIO_BLOQUES = 8;
const Y_INICIAL_BLOQUES = 40;
const MARGEN_BLOQUES =
  (anchoJuego - (BLOQUES_POR_FILA * ANCHO_BLOQUE + (BLOQUES_POR_FILA - 1) * ESPACIO_BLOQUES)) / 2;

// --- El estado del juego ---

type EstadoJuego = 'jugando' | 'perdido' | 'ganado';

type Bloque = { x: number; y: number; vivo: boolean };

type Juego = {
  estado: EstadoJuego;
  jugadorX: number;
  pelota: { x: number; y: number; vx: number; vy: number };
  bloques: Bloque[];
};

// Genera la cuadrícula completa de bloques, todos vivos.
function crearBloques(): Bloque[] {
  const bloques: Bloque[] = [];
  for (let fila = 0; fila < FILAS_BLOQUES; fila++) {
    for (let columna = 0; columna < BLOQUES_POR_FILA; columna++) {
      bloques.push({
        x: MARGEN_BLOQUES + columna * (ANCHO_BLOQUE + ESPACIO_BLOQUES),
        y: Y_INICIAL_BLOQUES + fila * (ALTO_BLOQUE + ESPACIO_BLOQUES),
        vivo: true,
      });
    }
  }
  return bloques;
}

function crearEstadoInicial(): Juego {
  return {
    estado: 'jugando',
    jugadorX: (anchoJuego - ANCHO_JUGADOR) / 2,
    pelota: {
      x: anchoJuego / 2,
      y: altoJuego / 2,
      vx: VELOCIDAD_INICIAL_PELOTA,
      vy: VELOCIDAD_INICIAL_PELOTA,
    },
    bloques: crearBloques(),
  };
}

// Mueve la pelota, resuelve rebotes con paredes/paleta/bloques, y decide
// si la partida se gana o se pierde. Todo mutando "juego" directamente.
function actualizarFisica(juego: Juego) {
  if (juego.estado !== 'jugando') return;

  const pelota = juego.pelota;
  pelota.x += pelota.vx;
  pelota.y += pelota.vy;

  if (pelota.x <= 0 || pelota.x >= anchoJuego - TAMANO_PELOTA) {
    pelota.vx = -pelota.vx;
  }
  if (pelota.y <= 0) {
    pelota.vy = -pelota.vy;
  }

  const tocaAlturaPaleta = pelota.y + TAMANO_PELOTA >= Y_JUGADOR && pelota.y <= Y_JUGADOR + ALTO_JUGADOR;
  const tocaAnchoPaleta = pelota.x + TAMANO_PELOTA >= juego.jugadorX && pelota.x <= juego.jugadorX + ANCHO_JUGADOR;
  if (pelota.vy > 0 && tocaAlturaPaleta && tocaAnchoPaleta) {
    pelota.vy = -pelota.vy;
  }

  // NUEVO: colisión con los bloques. Recorremos solo los que siguen vivos;
  // con el primero que coincida basta (para un Arkanoid "muy sencillo" no
  // hace falta resolver más de un golpe por frame).
  for (const bloque of juego.bloques) {
    if (!bloque.vivo) continue;

    const chocaEnX = pelota.x + TAMANO_PELOTA >= bloque.x && pelota.x <= bloque.x + ANCHO_BLOQUE;
    const chocaEnY = pelota.y + TAMANO_PELOTA >= bloque.y && pelota.y <= bloque.y + ALTO_BLOQUE;

    if (chocaEnX && chocaEnY) {
      bloque.vivo = false; // el bloque se rompe
      pelota.vy = -pelota.vy; // y la pelota rebota
      break;
    }
  }

  // Victoria: no queda ningún bloque vivo.
  if (juego.bloques.every((bloque) => !bloque.vivo)) {
    juego.estado = 'ganado';
  }

  // Derrota: la pelota pasó de largo la paleta.
  if (pelota.y > altoJuego) {
    juego.estado = 'perdido';
  }
}

Retos extra

Añade una puntuación: un campo puntos en Juego que suba al romper cada bloque, mostrado en un Text encima del área de juego.

Añade vidas: en vez de perder al primer fallo, resta una vida y llama a algo parecido a reiniciar() pero conservando los bloques que ya quedaban rotos.

Haz que la pelota acelere un poco cada vez que rompe un bloque (multiplica vx y vy por, por ejemplo, 1.03), para que la partida se ponga más difícil según avanza.

Si algo falla

La paleta no se mueve al arrastrar

Comprueba que {'{...panResponder.panHandlers}'} está puesto en la View del área de juego (la que tiene position: 'relative'), no en una View exterior. El PanResponder solo sigue el dedo dentro del elemento al que está conectado.

La pelota atraviesa la paleta o los bloques sin rebotar

Revisa el orden de las comprobaciones dentro de actualizarFisica: si TAMANO_PELOTA, ANCHO_JUGADOR o ANCHO_BLOQUE no coinciden con los que usas al dibujar (en los estilos), los rectángulos de colisión no encajan con lo que ves en pantalla.

La pelota se queda “pegada”, rebotando muy rápido en el mismo sitio

Suele pasar si el rebote de la paleta no comprueba pelota.vy > 0: sin esa condición, mientras la pelota siga solapada con la paleta unos frames, puede invertir su velocidad varias veces seguidas.

Al probar en el navegador (w en la terminal) no pasa nada al arrastrar con el ratón

PanResponder también funciona con el ratón gracias a react-native-web, pero asegúrate de mantener pulsado el botón mientras mueves el cursor (arrastrar de verdad, no solo pasar por encima).
