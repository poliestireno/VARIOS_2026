Temario de módulo · 2º ASIR

Administración de Sistemas Gestores de Bases de Datos

De MySQL/MariaDB y PostgreSQL como gestores relacionales clásicos, a SQLite como motor embebido, y al mundo NoSQL — MongoDB, Redis, Cassandra, DynamoDB — con Docker como forma habitual de desplegarlos. Organizado en desafíos agrupados por resultado de aprendizaje (RA).

3 bloques (RA1–RA6) 8 desafíos Eval. 1 + 2 · Eval. 3 = FFE
Bloque % eval. Desafíos Evaluación
RA1 + RA2 34% 2 Eval. 1
RA3 + RA4 33% 2 Eval. 1
RA5 + RA6 33% 4 Eval. 2
Bloque 1 · 34% de la evaluación

RA1 + RA2 · Implantación y configuración del SGBD

2 desafíos · Eval. 1

RA1. Implanta sistemas gestores de bases de datos analizando sus características y ajustándose a los requerimientos del sistema. RA2. Configura el sistema gestor de bases de datos interpretando las especificaciones técnicas y los requisitos de explotación.

Teoría

T0

La máquina virtual de desarrollo

Antes de empezar: instalar VirtualBox, montar una VM con Linux Mint XFCE (4 GB RAM, 20-25 GB de disco), y dejar dentro el stack de desarrollo completo (VS Code, Python, Apache, MariaDB, PHP).

T1

Administración de MySQL/MariaDB

Usuarios por host, GRANT/REVOKE, la tabla mysql.user y FLUSH PRIVILEGES, el fin de PASSWORD(), y los 15 parámetros de configuración que ajustan rendimiento y comportamiento del servidor.

Desafíos

D1

RA12_DBA_MYSQL

Como DBA de una consultora, configura los 15 parámetros de MySQL/MariaDB para 3 empresas distintas a partir de extractos de entrevista, justificando cada valor e indicando en qué fichero se aplica.

D2

RA12_USERS_MYSQL

Crea una base de datos de una red social (usuarios, grupos, comentarios) en MySQL/MariaDB sobre Kali Linux, y gestiona 25 ejercicios de creación de usuarios, permisos GRANT/REVOKE y privilegios, todo documentado con pantallazos.

Bloque 2 · 33% de la evaluación

RA3 + RA4 · Control de acceso y automatización

2 desafíos · Eval. 1

RA3. Implanta métodos de control de acceso utilizando asistentes, herramientas gráficas y comandos del lenguaje del sistema gestor. RA4. Automatiza tareas de administración del gestor describiéndolas y utilizando guiones de sentencias.

Teoría

T2

SQLite: la base de datos embebida

Instalación, tablas, CRUD, claves y restricciones, joins, seguridad de un fichero único, y optimización con índices, VACUUM y EXPLAIN QUERY PLAN.

T3

PostgreSQL: roles, permisos y tipos avanzados

Instalación y psql, roles con distinto nivel de permiso, columnas JSON y ARRAY, vistas materializadas, herencia de tablas, y pgAdmin.

Desafíos

D3

RA34_DBA_SQLITE

Como DBA de una app de gestión de frutas, configura y estructura una base SQLite, optimiza su rendimiento justificándolo con un log de consultas real analizado con EXPLAIN QUERY PLAN, implementa copias de seguridad automatizadas, y responde preguntas de seguridad sin IA.

D4

RA34_POSTGRES_DBA

Gestiona una base de datos de equitación (jinetes y caballos) en PostgreSQL: roles con distintos niveles de permiso, inserción y consulta de datos, y características avanzadas — JSON, ARRAY, vistas materializadas y herencia de tablas — desde psql y desde pgAdmin.

Bloque 3 · 33% de la evaluación

RA5 + RA6 · Rendimiento y disponibilidad: el mundo NoSQL

4 desafíos · Eval. 2

RA5. Optimiza el rendimiento del sistema aplicando técnicas de monitorización y realizando adaptaciones. RA6. Aplica criterios de disponibilidad analizándolos y ajustando la configuración del sistema.

Teoría

T4

Panorama NoSQL: Redis, Cassandra y DynamoDB

Cuándo elegir SQL y cuándo NoSQL, y una primera pasada por tres gestores muy distintos: en memoria, distribuido de columna ancha, y gestionado en la nube.

T5

Docker: contenedores para bases de datos

Imágenes y contenedores, Docker frente a una máquina virtual, comandos básicos, y cómo desplegar MongoDB con persistencia en un único docker run.

T6

MongoDB: bases de datos orientadas a documentos

El modelo de documentos, uso básico desde mongosh y Compass, JSON, operadores de consulta, y cómo modelar relaciones 1:1, 1:N y N:M con $lookup.

T7

Redis: estructuras de datos en memoria

Claves con TTL, listas, conjuntos, hashes y conjuntos ordenados, persistencia con RDB/AOF, y Redis desde PHP como caché delante de MySQL.

Desafíos

D5

RA56_NO_SOY_UN_MONGO

Instala MongoDB en Docker, explica sus características clave (documentos, NoSQL, escalabilidad, HA, índices, agregaciones), y traduce dos esquemas relacionales — frutas y un comercio — a colecciones MongoDB, con las mismas consultas resueltas desde terminal y desde Compass.

D6

RA56_ESTUDIO_3_GESTORES_NOSQL

Trabajo por clanes: estudio comparativo de Redis, Cassandra y Amazon DynamoDB, con documentación de cada uno y de sus diferencias, eportfolio individual, y exposición en clase repartida equitativamente.

D7

RA56_REDIS_CHALLENGE_FASE01

Instalación de Redis y recorrido completo de comandos — claves, TTL, listas, conjuntos, hashes, administración y backups — más un cliente visual (RedisInsight) y ejercicios de inventario, carrito de compra, ranking y control de tareas.

D8

RA56_REDIS_CHALLENGE_FASE02

Redis desde PHP con la extensión php-redis: conexión, hashes y listas, y la app “Aceitunas” (vareadores y olivos, relación M:N) con persistencia en MySQL y Redis como caché con TTL distinto para claves numéricas y de texto.

RA1+RA2 y RA3+RA4 se evalúan juntos en la primera evaluación: primero la implantación y configuración del SGBD relacional (MySQL, luego SQLite y PostgreSQL), después el control de acceso y la automatización. El bloque RA5+RA6 (rendimiento, disponibilidad y NoSQL) se cierra en la segunda evaluación. La tercera evaluación corresponde a la FFE (Formación en Centros de Trabajo).

El enunciado completo de cada desafío vive en un repositorio privado — los enlaces de esta página solo se abren con acceso a él. El encaje entre evaluaciones es orientativo y puede ajustarse.
