01

Qué es Docker

Docker usa la tecnología de contenedores para encapsular una aplicación y todas sus dependencias (librerías, binarios…) en una unidad independiente y portable: la imagen. Un contenedor es una instancia ejecutable de una imagen — ligero y rápido de arrancar. Docker Hub es el repositorio público donde buscar, descargar y publicar imágenes ya hechas (MySQL, PostgreSQL, MongoDB, Redis… todas tienen imagen oficial).

Ventajas principales: portabilidad (la misma imagen funciona igual en cualquier máquina con Docker), ligereza (los contenedores comparten el kernel del sistema anfitrión, no necesitan un SO completo cada uno), y encaje natural en pipelines de CI/CD.

03

Comandos básicos

$ docker --version
# muestra la versión instalada

$ docker pull ubuntu
# descarga una imagen desde Docker Hub

$ docker images
# lista las imágenes descargadas localmente

$ docker run -it ubuntu
# crea y ejecuta un contenedor interactivo

$ docker ps
# contenedores en ejecución
$ docker ps -a
# todos los contenedores, incluidos los detenidos

$ docker stop <id_contenedor>
$ docker rm <id_contenedor>
# detener y eliminar un contenedor

$ docker rmi <id_imagen>
# eliminar una imagen local

$ docker logs <id_contenedor>
$ docker exec -it <id_contenedor> bash
# ver logs / abrir una shell dentro de un contenedor en marcha
04

hello-world paso a paso

$ docker pull hello-world
# conecta con Docker Hub, descarga la imagen y la guarda localmente

$ docker run hello-world
# comprueba si la imagen existe local; si no, la descarga; crea y ejecuta el contenedor

$ docker images
$ docker ps -a
05

Desplegar MongoDB en Docker

$ docker run -d --name mongodb -p 27017:27017 \
  -e MONGO_INITDB_ROOT_USERNAME=admin \
  -e MONGO_INITDB_ROOT_PASSWORD=admin123 \
  -v /TU_DIRECTORIO/mongo_data:/data/db \
  mongo
  • -d: ejecuta el contenedor en segundo plano.
  • --name mongodb: nombre del contenedor.
  • -p 27017:27017: mapea el puerto local al puerto del contenedor.
  • -e MONGO_INITDB_ROOT_USERNAME / _PASSWORD: credenciales del usuario administrador.
  • -v: crea un volumen para persistencia — los datos sobreviven aunque se borre el contenedor.
$ docker ps
# comprueba que el contenedor mongodb está corriendo

$ docker stop mongodb
$ docker start mongodb
# buena práctica: parar en vez de eliminar, para no perder los datos
