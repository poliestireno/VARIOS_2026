Presentación

En este tema introducimos uno de los paradigmas más utilizados en el desarrollo de software moderno: la programación orientada a objetos (POO). A diferencia de la programación estructurada, la POO permite organizar el código de forma más lógica y modular, simulando cómo funcionan los objetos del mundo real. Trabajaremos paso a paso sus elementos clave — clases, atributos, métodos, encapsulamiento, herencia, polimorfismo y abstracción — y cómo aplicarlos en Python con ejemplos prácticos. El objetivo es que, al terminar este bloque, se pueda diseñar y construir programas propios aplicando correctamente estos principios: no solo para escribir mejor código, sino para poder abordar proyectos más complejos y trabajar de forma profesional en cualquier entorno de desarrollo.

01

Programación orientada a objetos

La POO es un paradigma de programación que organiza el código de forma más estructurada, reutilizable y cercana a cómo entendemos el mundo real. En vez de pensar en funciones sueltas y bloques de código, la POO se basa en objetos: entidades que agrupan datos (atributos) y comportamientos (métodos) en una misma unidad llamada clase.

Este enfoque permite modelar elementos del mundo real dentro del programa. Por ejemplo, para representar un coche, en vez de usar varias variables sueltas se puede crear una clase Coche con atributos como color, marca o velocidad, y métodos como acelerar() o frenar(), de forma que todo pertenezca al mismo elemento — el código resulta más fácil de entender, mantener y escalar.

No es obligatorio usar POO en un programa, pero aporta características muy valiosas para afrontar proyectos grandes:

  • Organización del código: agrupa datos y funciones relacionadas en un mismo objeto.
  • Reutilización: las clases se reutilizan en distintos programas o partes de un mismo proyecto, reduciendo mucho la cantidad de código a escribir.
  • Facilidad para ampliar: mejorar o extender una funcionalidad se hace sobre una clase concreta, sin afectar al resto del sistema.
  • Simulación del mundo real: modela objetos como usuarios, productos o vehículos, facilitando representar la lógica de negocio.
02

Conceptos fundamentales

Antes de programar, conviene tener claros los conceptos en los que se basa este paradigma.

02.1

Clases

Las clases son las plantillas — con atributos y métodos — que después se van moldeando según las necesidades del programa. Para definir una clase se usa la palabra reservada class, normalmente en un archivo independiente:

class Usuario:
    def __init__(self, nombre, edad, nota):
        self.nombre = nombre
        self.edad = edad
        self.nota = nota

El código crea una clase Usuario con nombre, edad y nota. Dentro de la clase se define una función especial, el constructor, que permite instanciar (hacer realidad) un objeto de esa clase. Se llama siempre __init__, y su primer parámetro es siempre self — hace referencia al propio objeto —, seguido de los atributos que forman parte de él. Dentro del constructor se hace la asignación, por ejemplo self.nombre = nombre, igualando la variable del objeto con el parámetro recibido.

Para instanciar el objeto desde otro archivo, se llama al constructor:

import objetos

alumno = objetos.Usuario("Gilbert", "Martin", 9)
print(alumno.nombre)
Un único constructor, pero flexible

A diferencia de otros lenguajes como Java o C#, Python no permite varios constructores para la misma clase — solo hay un __init__. Lo que sí se puede hacer es combinarlo con parámetros por defecto y con *args para que admita llamadas distintas:

class Usuario:
    def __init__(self, nombre, edad, *datos, nota=0):
        self.nombre = nombre
        self.edad = edad
        self.nota = nota
        self.datos = datos

    def mostrar_datos(self):
        print(f"Nombre: {self.nombre}")
        print(f"Edad: {self.edad}")
        print(f"Nota: {self.nota}")
        for dato in self.datos:
            print(f"Datos adicionales: {dato}")

Aquí, nota es un parámetro por defecto (0 si no se indica) y *datos admite tantos datos adicionales como se quiera:

alumno = objetos.Usuario(
    "Juan", 20,
    "Estudiante de Ingeniería", "Becado por la universidad", "Convalidaciones en curso",
    nota=9,
)
alumno1 = objetos.Usuario("Pedro", 22)  # nota=0 y datos=()

Además del constructor, una clase puede tener tantos métodos como haga falta — todos con self como primer parámetro, para acceder a las variables del propio objeto.

02.2

Atributos

Los atributos representan las características del objeto — su estado — y su valor depende de cómo se haya creado cada instancia. Se definen nombrándolos en el constructor y asignándolos a través de self:

class Empleado:
    def __init__(self, nombre, puesto, salario=1500, *tareas):
        self.nombre = nombre
        self.puesto = puesto
        self.salario = salario

Cada uno de estos atributos, definidos en el constructor, se llama atributo de instancia, porque pertenece al objeto. Para acceder a ellos desde un método basta con usar self:

    def mostrar_info(self):
        print(f"Nombre: {self.nombre}")
        print(f"Puesto: {self.puesto}")
        print(f"Salario: {self.salario} €")

Además de los atributos de instancia, existen los atributos de clase: se definen dentro de la clase, pero no en el constructor ni asignados vía self, sino directamente.

class Empleado:
    contratado = True
02.3

Métodos

Si los atributos son las características del objeto, los métodos son la funcionalidad que puede ejecutar. Se definen como funciones normales (pudiendo usar valores por defecto, *args o **kwargs), con la particularidad de llevar self como primer parámetro — la instancia sobre la que se ejecuta el método — para poder acceder a sus atributos y demás métodos.

class Empleado:
    contratado = True

    def __init__(self, nombre, puesto, salario=1500, *tareas):
        self.nombre = nombre
        self.puesto = puesto
        self.salario = salario
        self.tareas = tareas

    def mostrar_info(self):
        print(f"Nombre: {self.nombre}")
        print(f"Puesto: {self.puesto}")
        print(f"Salario: {self.salario} €")
        print(f"Contratado: {self.contratado}")
        print("Tareas asignadas:")
        if self.tareas:
            for t in self.tareas:
                print(f" - {t}")
        else:
            print(" (Sin tareas asignadas)")

Un método definido sin self no pertenece al objeto (no puede acceder a sus atributos). Para llamar a un método normal (de instancia) hace falta un objeto de la clase:

empleado1 = objetos.Empleado("Laura", "Recepcionista")
empleado1.mostrar_info()

La excepción es el método estático: se puede llamar directamente desde el nombre de la clase, sin necesidad de un objeto, marcándolo con el decorador @staticmethod.

    @staticmethod
    def mostrar_informacion_estatica():
        print("Ejecución directa del método")
objetos.Empleado.mostrar_informacion_estatica()

Si se intentara llamar así a un método de instancia (con self), se obtendría un error por falta de ese parámetro.

03

Principios de la POO

La POO organiza el código de forma modular, diferenciando elementos que se pueden tratar de manera independiente. Este modelado se apoya en cuatro principios: encapsulamiento, herencia, polimorfismo y abstracción.

03.1

Abstracción

Consiste en ocultar los detalles internos de funcionamiento de un objeto, mostrando solo lo necesario para su uso. En programación se consigue creando clases que representan conceptos del mundo real, con sus atributos (datos) y métodos (comportamientos) — una de las grandes ventajas de la POO es precisamente poder crear un objeto que se asemeje a lo que se maneja en la vida real, facilitando proponer e implementar una solución sencilla.

03.2

Encapsulamiento

Todo objeto tiene propiedades (atributos) y funcionalidades (métodos) definidos según las necesidades del programa. El encapsulamiento es el principio por el cual los datos de un objeto se protegen, para que no se puedan modificar directamente desde otra parte del programa. Otros lenguajes cuentan con modificadores de acceso para esto; en Python, al no existir, el control se hace mediante convenciones — anteponiendo __ al nombre del atributo se marca como privado.

class Estudiante:
    def __init__(self, nombre, nota):
        self.nombre = nombre
        self.__nota = nota

    def modificar_nota(self, nueva_nota):
        self.__nota = nueva_nota

    def mostrar_nota(self):
        print(f"Nota: {self.__nota}")

Para acceder a un atributo privado hace falta un método propio de la clase (un getter) — acceder a él directamente desde fuera da error:

from objetos import Estudiante

estudiante = Estudiante("Juan", 8)
estudiante.modificar_nota(10)
estudiante.mostrar_nota()
print(estudiante.__nota)  # error: no se puede acceder directamente a un atributo "privado"
03.3

Herencia

La herencia permite crear una clase nueva que aprovecha el comportamiento de otra ya existente — como si la nueva clase heredase todas las características de la original, pudiendo además añadir las suyas propias o modificar alguna de las heredadas. En vez de repetir código común entre varias clases, se coloca en una clase “padre” (o base), y las clases “hijas” (derivadas) heredan de ella.

Antes de programar, diagrama de clases

Antes de escribir código, conviene tener un diagrama de clases que muestre estas relaciones de herencia. Herramientas online gratuitas como Lucidchart traen plantillas ya preparadas para diagramas UML de clases.

Imagina un programa que controla los trabajadores de una empresa, diferenciando entre gerentes y desarrolladores — ambos comparten algunas características (nombre, salario) y difieren en otras (lenguaje de un desarrollador, departamento de un gerente). Habrá, por tanto, una clase común con lo compartido:

class Empleado:
    def __init__(self, nombre, salario):
        self.nombre = nombre
        self.salario = salario

    def mostrar_info(self):
        print(f"Empleado: {self.nombre}, Salario: ${self.salario}")

Y las clases hijas, indicando entre paréntesis de quién heredan:

class Gerente(Empleado):
    def __init__(self, nombre, salario, departamento):
        super().__init__(nombre, salario)
        self.departamento = departamento

    def mostrar_info(self):
        super().mostrar_info()
        print(f"Departamento a cargo: {self.departamento}")

class Desarrollador(Empleado):
    def __init__(self, nombre, salario, lenguaje):
        super().__init__(nombre, salario)
        self.lenguaje = lenguaje

    def mostrar_info(self):
        super().mostrar_info()
        print(f"Lenguaje de programación: {self.lenguaje}")

super() da acceso a lo definido en la superclase — se ve en mostrar_info(), y también se puede usar en el constructor, como aquí, para llamar al constructor de la clase padre. Usando estas clases:

desarrollador = Desarrollador("Gilbert", 50000, "Python")
gerente = Gerente("Laura", 70000, "IT")
desarrollador.mostrar_info()
gerente.mostrar_info()
Empleado: Gilbert, Salario: $50000
Lenguaje de programación: Python
Empleado: Laura, Salario: $70000
Departamento a cargo: IT
Herencia múltiple

A diferencia de otros lenguajes, en Python una clase puede heredar de varias a la vez. Retomando Gerente y Desarrollador:

class DirectorTecnico(Gerente, Desarrollador):
    def __init__(self, nombre, salario, departamento, lenguaje):
        Gerente.__init__(self, nombre, salario, departamento)
        Desarrollador.__init__(self, nombre, salario, lenguaje)

    def mostrar_info(self):
        super().mostrar_info()
        print(f"(También programa en: {self.lenguaje})")

DirectorTecnico hereda de ambas clases, accediendo a cada una con NombreClase.__init__(...) en el constructor. Cuando dos clases de las que se hereda tienen un método con el mismo nombre —aquí, mostrar_info está en Gerente y en Desarrollador— Python decide cuál usar con el MRO (method resolution order): se toma el método de la primera clase indicada en la firma, en este caso Gerente.

La sobrescritura de métodos heredados sigue funcionando igual que se ha visto: no hace falta ninguna palabra reservada especial, basta con volver a definir el método con el nuevo comportamiento (usando super() si se quiere reutilizar también el de la clase superior).

03.4

Polimorfismo

El último principio es el polimorfismo: permite que un objeto tome formas distintas según cómo haya sido creado. Para aplicarlo hace falta antes una línea de herencia válida, que permita a la clase hija comportarse tanto como ella misma como en la forma de su clase padre.

class Empleado:
    def __init__(self, nombre, salario):
        self.nombre = nombre
        self.salario = salario

    def trabajar(self):
        print(f"{self.nombre} está trabajando en tareas generales.")

class Gerente(Empleado):
    def __init__(self, nombre, salario, departamento):
        super().__init__(nombre, salario)
        self.departamento = departamento

    def trabajar(self):
        print(f"{self.nombre} está gestionando el departamento de {self.departamento}.")

class Desarrollador(Empleado):
    def __init__(self, nombre, salario, lenguaje):
        super().__init__(nombre, salario)
        self.lenguaje = lenguaje

    def trabajar(self):
        print(f"{self.nombre} está programando en {self.lenguaje}.")

empleados = [
    Gerente("Ana", 5000, "Marketing"),
    Desarrollador("Luis", 4000, "Python"),
    Empleado("Marta", 3000),
]

for empleado in empleados:
    empleado.trabajar()

Las tres clases se pueden instanciar por su cuenta con normalidad. Lo interesante del polimorfismo es que, como Gerente y Desarrollador heredan de Empleado, se pueden juntar en una misma lista y recorrerla llamando a un método común (trabajar()) — cada ejecución es distinta, porque lo que realmente se ejecuta es el método de la clase final de cada objeto, no el de Empleado.

Ejercicio

Estás desarrollando un pequeño sistema para una cafetería, que debe registrar distintos tipos de producto (cafés, tés, bollería), llevar el control de los pedidos y calcular el precio total.

  • Una clase Producto, con nombre, precio y un método mostrar_info.
  • Tres clases derivadas de Producto, cada una sobrescribiendo mostrar_info:
    • Bebida, con un atributo adicional tipo (string).
    • Comida, con un atributo adicional caliente (boolean).
    • Menu, con un atributo adicional completo (boolean).
  • Una clase Pedido, que contenga tantos productos como el cliente necesite, y un atributo con el coste total calculado.

Genera un par de pedidos con productos dentro, o construye un pequeño menú por consola para gestionarlos.

—

Conclusiones

En este tema hemos visto los fundamentos de la programación orientada a objetos en Python: usar clases, atributos y métodos para modelar objetos del mundo real, y aplicar herencia, encapsulamiento, abstracción y polimorfismo para escribir código más limpio, reutilizable y fácil de mantener.

La POO organiza el código de forma estructurada, algo fundamental en proyectos medianos y grandes: permite dividir problemas complejos en partes más pequeñas, reutilizar soluciones ya construidas y facilitar el trabajo en equipo. Entender y aplicar bien estos conceptos no solo mejora la forma de programar, sino que prepara para usar frameworks y librerías modernas, la mayoría construidas sobre este mismo paradigma.
