Guardar datos

Que la app recuerde algo al cerrarla y reabrirla: instalamos AsyncStorage, guardamos y leemos JSON en el disco del móvil, y montamos el patrón “cargar al abrir, guardar en cada cambio” que usaréis en casi cualquier app real.

Punto de partida

Todo lo que habéis construido hasta ahora tiene el mismo defecto: cerráis la app y desaparece. El estado de React vive en la memoria mientras la app está abierta, y punto. Hoy vais a cruzar esa frontera: guardar algo en el propio móvil, en un almacenamiento que sobrevive a cerrar la app, apagar el teléfono o incluso desinstalar Expo Go y volver a abrir el proyecto.

1 · Instalar AsyncStorage

No viene incluido en React Native puro: es un paquete aparte, mantenido por la comunidad de React Native (antes vivía dentro del propio RN, de ahí el nombre). Se instala con el comando de Expo, no con npm install a secas, para que Expo elija la versión compatible con vuestro SDK.

$ npx expo install @react-native-async-storage/async-storage

Como instala un módulo nativo, hace falta reiniciar el servidor (Ctrl+C y npm start de nuevo) para que Expo Go lo reconozca.

2 · setItem y getItem son asíncronos

Leer o escribir en el disco del móvil no es instantáneo, así que las dos operaciones básicas devuelven una Promise: hace falta await (dentro de una función async) o .then().

import AsyncStorage from '@react-native-async-storage/async-storage';

// guardar
await AsyncStorage.setItem('nombre', 'Ana');

// leer
const valor = await AsyncStorage.getItem('nombre');
console.log(valor); // 'Ana'

Ambas claves y valores son siempre strings. Es una limitación importante: AsyncStorage no sabe nada de objetos, arrays ni números, solo texto.

3 · Por qué stringify y parse

Como solo se guardan strings, cualquier dato que no sea ya texto —un array de tareas, un objeto de configuración— hay que convertirlo antes de guardarlo con JSON.stringify, y devolverlo a su forma original al leerlo con JSON.parse.

const tareas = [
  { id: '1', texto: 'Comprar pan', hecha: false },
  { id: '2', texto: 'Estudiar RN', hecha: true },
];

// guardar el array entero como un único string JSON
await AsyncStorage.setItem('tareas', JSON.stringify(tareas));

// leerlo y reconstruir el array
const guardado = await AsyncStorage.getItem('tareas');
const tareasRecuperadas = guardado ? JSON.parse(guardado) : [];
getItem devuelve null si la clave no existe

La primera vez que se abre la app no hay nada guardado todavía: getItem devuelve null, no un string vacío. Hacer JSON.parse(null) directamente da un error —por eso el patrón siempre comprueba antes: guardado ? JSON.parse(guardado) : valorPorDefecto.

4 · El patrón: cargar al montar, guardar en cada cambio

Casi cualquier pantalla con persistencia sigue la misma forma: un useEffect que lee de AsyncStorage una sola vez al montar (array de dependencias vacío), y otro useEffect que guarda cada vez que el estado relevante cambia.

import { useState, useEffect } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';

const CLAVE = 'tareas';

export default function App() {
  const [tareas, setTareas] = useState([]);
  const [cargado, setCargado] = useState(false);

  // 1. cargar una vez, al montar
  useEffect(() => {
    async function cargar() {
      const guardado = await AsyncStorage.getItem(CLAVE);
      if (guardado) setTareas(JSON.parse(guardado));
      setCargado(true);
    }
    cargar();
  }, []);

  // 2. guardar cada vez que "tareas" cambia
  useEffect(() => {
    if (!cargado) return; // evita sobrescribir con [] antes de cargar
    AsyncStorage.setItem(CLAVE, JSON.stringify(tareas));
  }, [tareas, cargado]);

  // ... resto del componente
}

El flag cargado evita un bug muy común: sin él, el segundo useEffect se ejecuta también en el primer render (cuando tareas todavía es []), y guarda una lista vacía antes de que la carga real haya terminado —borrando sin querer lo que ya había guardado.

Aplicad el patrón de carga/guardado

Los dos useEffect de la sección anterior, adaptados a vuestra clave y vuestro estado.

3

Probad cerrando la app de verdad

No basta con guardar el archivo y ver el Fast Refresh: hay que cerrar Expo Go desde el multitarea del móvil (deslizar hacia arriba para quitarla de la lista de apps recientes) y volver a abrirla escaneando o desde el historial reciente.

Debería funcionar así

Marcáis un favorito o añadís una tarea, cerráis la app del todo, la volvéis a abrir: el dato sigue ahí, sin necesidad de volver a pedirlo a la API ni de que el usuario lo repita.
