Antes de empezar

Esta es la última sesión de JavaScript puro antes de entrar en React Native. Todo lo de hoy encaja directamente con lo próximo: los componentes de una app se reparten en archivos (módulos), y casi cualquier app real necesita pedir datos a un servidor, lo cual siempre tarda un poco — de ahí el código asíncrono.

Los ejemplos de fetch funcionan tal cual pegados en la consola del navegador (F12 → Console), porque el navegador entiende fetch de forma nativa. Los ejemplos de módulos (import/export) son la excepción: no funcionan sueltos en la consola, solo dentro de un proyecto con varios archivos — como el que montaremos con Expo. Por ahora, léelos para entender la idea; los escribirás de verdad muy pronto.

Módulos: import y export

Hasta ahora todo el código ha vivido en un único sitio (la consola, o un archivo). En una aplicación real, el código se reparte en muchos archivos pequeños con una responsabilidad cada uno, y se conectan entre sí con export (para ofrecer algo) e import (para usarlo en otro archivo).

Imagina un archivo matematicas.js que ofrece varias utilidades:

// matematicas.js
export const PI = 3.1416;

export function sumar(a, b) {
  return a + b;
}

export default function multiplicar(a, b) {
  return a * b;
}

Y otro archivo, app.js, que los usa:

// app.js
import multiplicar, { PI, sumar } from './matematicas.js';

console.log(sumar(2, 3));       // 5
console.log(multiplicar(2, 3));  // 6
console.log(PI);                // 3.1416

Hay dos tipos de exportación, y se importan distinto: un archivo puede tener como mucho un export default (la cosa “principal” de ese archivo, se importa sin llaves y con el nombre que quieras), y tantos export con nombre como haga falta (se importan entre llaves, con su nombre exacto).

Esto ya lo has visto

Si has echado un ojo a la guía del contador en Expo, la primera línea de App.js es exactamente esto: import { useState } from 'react'. Estás importando una utilidad con nombre desde el módulo react, igual que en el ejemplo de arriba.

Template literals

Ya conocías la concatenación con +. Los template literals — strings entre comillas invertidas (`) — hacen lo mismo de forma más legible, insertando variables directamente con ${...}:

const nombre = "Ana";
const edad = 27;

// antes, con +
console.log("Hola, " + nombre + ". Tienes " + edad + " años.");

// con template literal
console.log(`Hola, ${nombre}. Tienes ${edad} años.`);
// "Hola, Ana. Tienes 27 años."

Dentro de ${...} puedes poner cualquier expresión de JavaScript, no solo una variable suelta:

console.log(`El doble de ${edad} es ${edad * 2}`);
// "El doble de 27 es 54"

También admiten varias líneas de verdad, sin trucos raros con \n:

const mensaje = `Primera línea
Segunda línea`;
console.log(mensaje);

Promesas: una analogía simple

Imagina que pides comida a domicilio por teléfono. Al colgar, no tienes la comida todavía — tienes una promesa de que va a llegar. Esa promesa puede acabar de dos formas: la comida llega (la promesa se cumple), o el restaurante cierra sin avisar y te llaman para decir que no pueden servirte (la promesa se rechaza). Mientras tanto, no te quedas parado esperando en la puerta: sigues con tu vida y reaccionas cuando pase una cosa u otra.

Una Promise en JavaScript es exactamente eso: un valor que todavía no existe, pero existirá — con éxito o con error — en algún momento.

const pedidoComida = new Promise((resolve, reject) => {
  const restauranteAbierto = true;

  if (restauranteAbierto) {
    resolve("Tu pizza está en camino");
  } else {
    reject("El restaurante está cerrado");
  }
});

pedidoComida
  .then(mensaje => console.log("✅ " + mensaje))
  .catch(error => console.log("❌ " + error));
// "✅ Tu pizza está en camino"

.then() recibe el valor cuando la promesa se cumple; .catch() recibe el error cuando se rechaza. En la práctica, tú casi nunca vas a crear promesas con new Promise(...) como arriba — eso ya lo hacen por ti funciones como fetch. Lo que sí harás constantemente es consumirlas.

Escribir varias operaciones asíncronas seguidas con .then() encadenados se vuelve difícil de leer rápido. async/await es una forma más limpia de escribir exactamente lo mismo, como si el código “esperara” de forma síncrona:

async function pedirComida() {
  try {
    const mensaje = await pedidoComida;
    console.log("✅ " + mensaje);
  } catch (error) {
    console.log("❌ " + error);
  }
}

pedirComida();

Las reglas son dos: await solo se puede usar dentro de una función marcada como async, y siempre “pausa” esa función hasta que la promesa se resuelva (con éxito o con error). El try/catch hace aquí el mismo papel que .then()/.catch() hacía arriba.

Una llamada real: fetch

fetch es la función del navegador para pedir datos a una URL por internet. Devuelve una Promise, así que se combina perfectamente con async/await. Vamos a usar JSONPlaceholder, una API pública, gratuita y sin necesidad de registrarte, pensada exactamente para practicar esto.

async function obtenerUnPost() {
  const respuesta = await fetch("https://jsonplaceholder.typicode.com/posts/1");
  const post = await respuesta.json();
  console.log(post);
}

obtenerUnPost();
// { userId: 1, id: 1, title: "sunt aut facere...", body: "quia et suscipit..." }

Fíjate en los dos await: el primero espera a que el servidor responda (fetch), y el segundo espera a que esa respuesta se convierta de texto crudo a un objeto de JavaScript (.json()) — ese segundo paso también es asíncrono, aunque suele ser instantáneo.

Pégalo en la consola

Este ejemplo funciona tal cual, pegado directamente en la consola del navegador. Pruébalo antes de seguir — es tu primera petición real a un servidor en internet.

Práctica

Vamos a combinar lo de hoy con lo de la sesión pasada: pedir una lista completa a la API, y procesarla con los métodos de array que ya conoces (slice, map, filter).

1

Trae la lista completa de posts

El endpoint /posts (sin número al final) devuelve un array con 100 posts. Empieza por traerlos todos y comprobar cuántos hay.

async function obtenerPosts() {
  const respuesta = await fetch("https://jsonplaceholder.typicode.com/posts");
  const posts = await respuesta.json();
  console.log(posts.length); // 100
  return posts;
}
2

Quédate con los 5 primeros

slice(0, 5) devuelve una copia del array recortada a las 5 primeras posiciones, sin tocar el array original — el mismo espíritu que map/filter de la sesión pasada.

async function obtenerPrimerosCinco() {
  const posts = await obtenerPosts();
  const primerosCinco = posts.slice(0, 5);
  console.log(primerosCinco);
}
3

Muestra solo los títulos

Cada post trae varios campos (userId, id, title, body). Usa map para quedarte solo con title, exactamente igual que hiciste con los nombres de los alumnos.

async function mostrarTitulos() {
  const posts = await obtenerPosts();
  const titulos = posts.slice(0, 5).map(post => post.title);
  console.log(titulos);
}

mostrarTitulos();
// ["sunt aut facere...", "qui est esse", "ea molestias quasi...", ...]
Deberías ver esto

Un array de 5 strings en la consola, cada uno el título de un post. Si ves undefined en vez de texto, revisa que estás escribiendo post.title y no post.titulo — la API responde en inglés.

4

Filtra por autor

Cada post tiene un userId (del 1 al 10). Combina filter con lo anterior para quedarte solo con los posts de un usuario concreto.

async function postsDelUsuario(userId) {
  const posts = await obtenerPosts();
  const deEseUsuario = posts.filter(post => post.userId === userId);
  console.log(`El usuario ${userId} tiene ${deEseUsuario.length} posts`);
  return deEseUsuario;
}

postsDelUsuario(3);
Reto extra

Trae la lista de usuarios en https://jsonplaceholder.typicode.com/users (también un array de objetos, con id y name) y escribe una función que reciba un userId y devuelva un mensaje del tipo "Ese usuario se llama Clementine Bauch y tiene 10 posts", combinando dos peticiones fetch distintas dentro de la misma función async. Como segundo reto: usa reduce sobre los 100 posts para contar cuántos posts tiene cada userId, sin hacer 10 peticiones separadas.
