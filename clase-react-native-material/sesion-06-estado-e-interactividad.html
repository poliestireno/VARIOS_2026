2 horas Sesión 6/24 useState + eventos

En la sesión 5 tus componentes recibían props y las pintaban, sin más. Pero una interfaz real cambia con el tiempo: un contador sube, una tarea se marca como hecha, un menú se abre y se cierra. React necesita una forma de decir “este dato puede cambiar, y cuando cambie, vuelve a dibujar lo que dependa de él”. Esa forma es el estado, y hoy es el protagonista. Seguimos en el navegador, con React normal.

Qué vas a aprender

  • Qué es useState y por qué el estado nunca se modifica directamente, siempre a través de su función set.
  • Cómo reaccionar a eventos del usuario, sobre todo onClick.
  • Cómo mostrar u ocultar cosas según una condición, con && y con el operador ternario.

useState: memoria propia de un componente

useState le da a un componente un valor que persiste entre renders, y una función para actualizarlo. Al llamarla, React vuelve a ejecutar el componente con el nuevo valor y actualiza solo lo que cambió en el DOM real.

import { useState } from "react";

function Contador() {
  const [cuenta, setCuenta] = useState(0);

  return (
    <div>
      <p>Valor: {cuenta}</p>
      <button onClick={() => setCuenta(cuenta + 1)}>
        Sumar 1
      </button>
    </div>
  );
}

useState(0) devuelve un array de dos posiciones: el valor actual (cuenta) y la única función autorizada para cambiarlo (setCuenta). cuenta = cuenta + 1 directamente no funcionaría: reasignar una constante rompe, y aunque no rompiera, React no se enteraría de que algo cambió y no volvería a dibujar la pantalla. setCuenta(...) es la señal que React necesita para saber que toca actualizar.

Con arrays y objetos, nunca mutar

Si el estado es un array o un objeto, tampoco se puede tocar por dentro (.push(), asignar una propiedad). React compara la referencia anterior con la nueva para decidir si algo cambió, y si mutas el mismo objeto, la referencia sigue siendo idéntica — React cree que nada cambió y no repinta.

// ❌ mal: mutar el array que ya existía
tareas.push(nuevaTarea);
setTareas(tareas);

// ✅ bien: construir un array nuevo
setTareas([...tareas, nuevaTarea]);

Renderizado condicional

JSX no admite un if suelto dentro del {'{ }'}, porque un if no devuelve un valor. Para mostrar algo solo bajo cierta condición se usan expresiones que sí devuelven valor: el operador && y el operador ternario ? :.

function Mensaje({ cuenta }) {
  return (
    <div>
      {cuenta === 0 && <p>Todavía no has sumado nada</p>}
      {cuenta > 0 ? (
        <p>Llevas {cuenta} puntos</p>
      ) : (
        <p>Empieza a sumar</p>
      )}
    </div>
  );
}

condición && algo muestra algo solo si la condición es verdadera (y no muestra nada — técnicamente false, que React ignora — si es falsa). El ternario sirve para elegir entre dos alternativas, como un if / else compacto.

Juntándolo todo: una lista de tareas

Un contador es útil para entender useState, pero una lista de tareas obliga a combinar todo lo de hoy: estado que es un array, un input controlado por ese estado, y tres acciones distintas sobre la lista.

function ListaTareas() {
  const [tareas, setTareas] = useState([]);
  const [texto, setTexto] = useState("");

  function anadirTarea() {
    if (texto.trim() === "") return;
    const nueva = { id: Date.now(), texto, hecha: false };
    setTareas([...tareas, nueva]);
    setTexto("");
  }

  function alternarTarea(id) {
    setTareas(
      tareas.map((t) => (t.id === id ? { ...t, hecha: !t.hecha } : t))
    );
  }

  function eliminarTarea(id) {
    setTareas(tareas.filter((t) => t.id !== id));
  }

  return (
    <div>
      <input
        value={texto}
        onChange={(e) => setTexto(e.target.value)}
        placeholder="Nueva tarea"
      />
      <button onClick={anadirTarea}>Añadir</button>

      <ul>
        {tareas.map((t) => (
          <li key={t.id}>
            <span
              onClick={() => alternarTarea(t.id)}
              style={{
                textDecoration: t.hecha ? "line-through" : "none",
              }}
            >
              {t.texto}
            </span>
            <button onClick={() => eliminarTarea(t.id)}>
              Eliminar
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}

Fíjate en el patrón que se repite en las tres funciones: ninguna toca tareas directamente, todas construyen una versión nueva (con [...tareas, nueva], .map() o .filter()) y se la pasan a setTareas. Es el mismo principio de “nunca mutar” de antes, aplicado tres veces.

La idea que se queda de hoy

El estado se lee directamente pero se cambia siempre a través de su función set, con un valor nuevo, nunca mutando el anterior. Cada cambio de estado provoca un nuevo render.

Marcar como hecha y eliminar

Cada tarea de la lista necesita una forma de marcarse como completada (cambia visualmente, por ejemplo con text-decoration) y un botón para eliminarla.

Deberías ver esto

Puedes escribir una tarea, pulsar “Añadir” y verla aparecer en la lista; puedes tachar tareas y quitarlas, y el input siempre queda vacío después de añadir.
