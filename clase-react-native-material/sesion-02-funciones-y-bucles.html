Funciones y bucles

Dejar de repetir código a mano: empaquetar lógica en funciones que se pueden reutilizar, y repetir tareas con bucles en lugar de copiar y pegar la misma línea diez veces.

Antes de empezar

Seguimos en la consola del navegador (F12 → Console) o en node desde la terminal, igual que la sesión pasada. Hoy el código empieza a tener varias líneas relacionadas entre sí, así que si tu entorno te lo permite, es más cómodo escribirlo primero en un archivo de texto y pegarlo entero en la consola, en vez de línea a línea.

Funciones: declaration vs arrow

Una función es un bloque de código con nombre que puedes ejecutar (“llamar”) tantas veces como quieras, con datos distintos cada vez. Es la herramienta contra la repetición: en vez de escribir la misma lógica varias veces, la escribes una y la invocas.

Hay dos formas habituales de escribirlas. La primera es la function declaration, la forma clásica:

function saludar(nombre) {
  return "Hola, " + nombre;
}

console.log(saludar("Marta")); // "Hola, Marta"

La segunda es la arrow function (función flecha), más compacta, y hoy la forma más habitual en código de React y React Native:

const saludar = (nombre) => {
  return "Hola, " + nombre;
};

console.log(saludar("Marta")); // "Hola, Marta"

Si el cuerpo de la función es una única línea que devuelve un valor, la arrow function admite una forma aún más corta, sin llaves ni return — el resultado de la expresión se devuelve solo:

const saludar = nombre => "Hola, " + nombre;

console.log(saludar("Marta")); // "Hola, Marta"
¿Cuál uso?

Para funciones sueltas y reutilizables (cálculos, transformaciones de datos), cualquiera de las dos sirve — muchos equipos prefieren arrow por brevedad. Cuando lleguemos a React Native usarás arrow functions casi siempre, sobre todo para funciones cortas que se pasan como argumento a otra (como veremos con onPress más adelante). Por ahora, quédate con la idea de que son dos sintaxis distintas para lo mismo.

Los datos que entran se llaman parámetros (nombre en el ejemplo), y lo que sale es el valor de retorno, la palabra return. Una función sin return explícito devuelve undefined:

function sinRetorno() {
  console.log("Hago algo, pero no devuelvo nada");
}

let resultado = sinRetorno();
console.log(resultado); // undefined

Bucles: for y while

Un bucle repite un bloque de código varias veces. El más común es for, que tiene tres partes separadas por punto y coma: dónde empieza el contador, hasta cuándo sigue, y cómo avanza en cada vuelta.

for (let i = 1; i <= 5; i++) {
  console.log(i);
}
// 1
// 2
// 3
// 4
// 5

Léelo así: let i = 1 — empieza en 1. i <= 5 — sigue mientras esto sea cierto. i++ — suma 1 a i al final de cada vuelta (es una forma corta de i = i + 1). En cuanto la condición deja de cumplirse, el bucle para.

while es más simple: repite mientras una condición sea verdadera, sin la estructura fija del for. Es útil cuando no sabes de antemano cuántas vueltas hará falta.

let saldo = 100;
let meses = 0;

while (saldo > 0) {
  saldo = saldo - 30;
  meses = meses + 1;
}

console.log(meses); // 4 -> tras 4 meses, el saldo queda en -20 y el bucle para
El error más típico: el bucle infinito

Si la condición del while nunca deja de ser cierta (por ejemplo, si olvidas la línea saldo = saldo - 30), el bucle no termina nunca y cuelga la pestaña o la terminal. Si te pasa, en el navegador cierra la pestaña; en node, pulsa Ctrl+C. Revisa siempre que algo dentro del bucle acerque la condición hacia false.

Scope: dentro y fuera de una función

El scope (ámbito) determina desde dónde se puede “ver” una variable. Una variable creada dentro de una función solo existe dentro de esa función — es invisible fuera, aunque la función ya se haya ejecutado.

function calcularDoble(numero) {
  const resultado = numero * 2;
  return resultado;
}

console.log(calcularDoble(5)); // 10
console.log(resultado); // ❌ ReferenceError: resultado is not defined

Al revés sí funciona: una función puede leer variables que existan fuera de ella, siempre que hayan sido declaradas antes de que la función se ejecute.

const impuesto = 0.21;

function precioConImpuesto(precioBase) {
  return precioBase * (1 + impuesto);
}

console.log(precioConImpuesto(100)); // 121

Esta idea — que cada función tiene su propio espacio privado de variables, y solo puede “asomarse” hacia fuera, nunca al revés — es la razón por la que se pueden escribir funciones cortas y reutilizables sin miedo a que pisen variables de otras partes del programa con el mismo nombre.

Práctica: FizzBuzz

FizzBuzz es el ejercicio clásico para practicar bucles y condicionales a la vez. La regla: recorre los números del 1 al 100. Para cada uno, si es múltiplo de 3 imprime "Fizz"; si es múltiplo de 5 imprime "Buzz"; si es múltiplo de ambos imprime "FizzBuzz"; si no es múltiplo de ninguno, imprime el número tal cual.

1

Monta el bucle vacío

Empieza por el esqueleto: un for que recorra del 1 al 100 e imprima cada número, sin lógica todavía.

for (let i = 1; i <= 100; i++) {
  console.log(i);
}
2

Detecta los múltiplos con %

Recuerda el operador módulo de la sesión pasada: i % 3 === 0 es cierto exactamente cuando i es múltiplo de 3, porque no deja resto.

console.log(9 % 3);  // 0 -> 9 es múltiplo de 3
console.log(10 % 3); // 1 -> 10 no lo es
3

Añade las condiciones, en el orden correcto

El caso “múltiplo de ambos” tiene que comprobarse primero, o nunca se alcanzará: si comprobaras “múltiplo de 3” antes, un número como 15 entraría ahí y nunca llegaría a la comprobación de “ambos”.

for (let i = 1; i <= 100; i++) {
  if (i % 3 === 0 && i % 5 === 0) {
    console.log("FizzBuzz");
  } else if (i % 3 === 0) {
    console.log("Fizz");
  } else if (i % 5 === 0) {
    console.log("Buzz");
  } else {
    console.log(i);
  }
}

&& es el operador “y”: la condición completa solo es cierta si las dos partes lo son.

4

Compruébalo

Deberías ver esto

Los primeros quince resultados: 1, 2, Fizz, 4, Buzz, Fizz, 7, 8, Fizz, Buzz, 11, Fizz, 13, 14, FizzBuzz. Si no coincide, revisa primero el orden de tus if/else if.

5

Empaquétalo en una función

Ahora que funciona, envuélvelo en una función reutilizable que reciba el límite como parámetro, en vez de dejarlo fijo en 100.

function fizzBuzz(limite) {
  for (let i = 1; i <= limite; i++) {
    if (i % 3 === 0 && i % 5 === 0) {
      console.log("FizzBuzz");
    } else if (i % 3 === 0) {
      console.log("Fizz");
    } else if (i % 5 === 0) {
      console.log("Buzz");
    } else {
      console.log(i);
    }
  }
}

fizzBuzz(20); // ahora puedes llamarla con cualquier límite
