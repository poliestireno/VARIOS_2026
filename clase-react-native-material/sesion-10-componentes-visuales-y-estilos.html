Image: dos formas de traer una imagen

Image es el componente para mostrar imágenes, y admite dos fuentes muy distintas según de dónde venga la imagen.

// Local: la imagen vive dentro de tu proyecto, en assets/
<Image source={require('./assets/avatar.png')} style={styles.avatar} />

// Remota: la imagen vive en un servidor
<Image source={{ uri: 'https://ejemplo.com/avatar.png' }} style={styles.avatar} />

require('./assets/avatar.png') hace que el empaquetador incluya esa imagen dentro de tu app en tiempo de compilación — por eso la ruta tiene que ser literal, no puede ser una variable. Con {{ uri: '...' }} le pasas una URL que se descarga en tiempo de ejecución, como un <img src="..."> de toda la vida.

Siempre dale un tamaño

A diferencia de la web, React Native no puede calcular solo el tamaño de una imagen remota antes de descargarla. Si no le das width/height (o flex) en el style, una Image con uri simplemente no se ve — ocupa cero espacio.

Pressable con retroalimentación al tacto

Ya usaste Pressable la sesión pasada para el botón del contador. Hoy vamos un paso más allá: su prop style también acepta una función, que recibe el estado actual del toque y te deja cambiar el aspecto mientras el dedo sigue sobre el botón.

<Pressable
  style={({ pressed }) => [
    styles.boton,
    pressed && styles.botonPresionado,
  ]}
  onPress={() => console.log('tocado')}
>
  <Text style={styles.textoBoton}>Seguir</Text>
</Pressable>

El array [styles.boton, pressed && styles.botonPresionado] es el patrón habitual para combinar estilos condicionalmente en RN: StyleSheet acepta un array de estilos y los mezcla en orden, así que si pressed es false, ese false simplemente se ignora.

ScrollView frente a View

Una View normal no hace scroll: si su contenido no cabe en la pantalla, el resto queda recortado y no hay forma de llegar a él tocando. ScrollView es un contenedor que sí permite desplazarse, pensado para contenido que puede superar el alto de la pantalla — un formulario largo, una pantalla de perfil con mucho texto, etc.

<ScrollView contentContainerStyle={styles.contenido}>
  <Text>Mucho contenido que puede no caber…</Text>
</ScrollView>

Fíjate en contentContainerStyle en vez de style: en un ScrollView, style afecta al contenedor del scroll (por ejemplo su flex: 1), mientras que contentContainerStyle afecta al contenido que se desplaza dentro — ahí es donde pones alignItems, padding, etc.

Adelanto de la próxima sesión

Para listas largas de datos (decenas o cientos de elementos), ScrollView es una mala idea: renderiza todo de golpe, aunque el usuario nunca llegue a verlo. En la Sesión 11 verás FlatList, pensada exactamente para eso.

Flexbox en React Native, con una trampa desde el primer día

React Native usa Flexbox para maquetar, igual que la web moderna — justifyContent, alignItems, gap, todo funciona igual. Pero hay una diferencia que sorprende a todo el mundo la primera vez: el flexDirection por defecto en React Native es 'column', no 'row' como en CSS web.

CSS (web) — fila por defecto 
.contenedor {
  display: flex;
  /* flex-direction: row; ← implícito */
}
React Native — columna por defecto 
const styles = StyleSheet.create({
  contenedor: {
    // flexDirection: 'column' ← implícito
  },
});

Tiene sentido si lo piensas desde el móvil: una pantalla es alta y estrecha, así que apilar elementos verticalmente es el caso común. Si quieres una fila de botones uno al lado de otro, tienes que pedirlo explícitamente con flexDirection: 'row'.

const styles = StyleSheet.create({
  fila: {
    flexDirection: 'row',
    justifyContent: 'space-between',
    alignItems: 'center',
    gap: 12,
  },
});

justifyContent reparte espacio en el eje principal (el que marca flexDirection) y alignItems en el eje cruzado — exactamente igual que en CSS. gap también funciona igual: espacio entre elementos, sin tener que meter márgenes a mano en cada uno.

Práctica

Construye una pantalla de perfil de usuario en tu App.js (o en un componente nuevo si prefieres separarlo). Todo el estilo tiene que salir de StyleSheet.create — nada de colores o tamaños sueltos escritos directamente en el JSX.

1

Foto de perfil

Una Image circular arriba del todo. Puedes usar una imagen que descargues a assets/ y cargarla con require(), o una uri remota (por ejemplo, de picsum.photos). Para que se vea redonda: width y height iguales, y borderRadius igual a la mitad de ese valor.

2

Nombre y bio

Dos Text debajo de la foto: uno con el nombre (más grande, en negrita) y otro con una bio corta (más pequeño, color atenuado). Envuélvelos junto con la foto en una View con alignItems: 'center'.

3

Dos botones en fila

Una View con flexDirection: 'row' y gap, conteniendo dos Pressable estilizados (por ejemplo “Seguir” y “Mensaje”), cada uno con su propio color de fondo. Usa el patrón de estilo condicional que hemos visto para que se oscurezcan ligeramente mientras se mantienen pulsados.

4

Envuélvelo en ScrollView

Aunque hoy quepa de sobra en pantalla, envuelve todo en un ScrollView en vez de una View — así, si añades más contenido (por ejemplo, una lista de intereses), la pantalla no se rompe.

Reto extra: añade una fila de tres “estadísticas” (por ejemplo, Publicaciones / Seguidores / Siguiendo), cada una como un número grande encima de una etiqueta pequeña, repartidas con justifyContent: 'space-around'.
