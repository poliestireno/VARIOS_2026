Pulido visual y build

Dejar la app lista para enseñarla fuera del aula: estilos consistentes, icono propio, y una build instalable de verdad — un APK que funciona sin Expo Go y sin pasar por Google Play.

2 horas Sesión 23/24 Android APK

Antes de empezar

  • Cada alumno necesita una cuenta gratuita de Expo (se crea en expo.dev). Es distinta de tener Expo Go instalado — hace falta cuenta para poder mandar builds a la nube.
  • El proyecto debe arrancar sin errores con npm start antes de tocar nada de esto — una build no arregla bugs, solo empaqueta lo que ya hay.
  • Conviene avisar con antelación de que la build tarda — se procesa en la nube de Expo, no en el portátil, así que no depende de la potencia de cada máquina, pero sí hay que esperar.

Checklist de estilos

Antes de tocar la configuración de la build, un repaso rápido de mesa en mesa — diez minutos, no una sesión entera:

  • Colores consistentes. Si cada pantalla usa un azul distinto porque se copió y pegó del StyleSheet de otra, es buen momento para centralizar dos o tres colores base en un solo sitio (un objeto simple, por ejemplo const colors = { primary: '#2563eb', ... }) y reutilizarlos.
  • Tamaños de texto legibles. Texto de cuerpo por debajo de 14–15px es difícil de leer en un móvil real, sobre todo enseñándolo a distancia en un demo day.
  • Espaciado con StyleSheet, no valores sueltos. Si hay marginTop: 13 y marginTop: 17 en sitios distintos porque “quedaba bien”, conviene unificar a valores redondos (8, 12, 16, 24) definidos en el StyleSheet del componente.

Icono y splash screen

Ambos se configuran en app.json, en la raíz del proyecto, sin tocar nada de código de las pantallas:

{
  "expo": {
    "name": "mi-app",
    "slug": "mi-app",
    "icon": "./assets/icon.png",
    "splash": {
      "image": "./assets/splash.png",
      "resizeMode": "contain",
      "backgroundColor": "#ffffff"
    },
    "android": {
      "package": "com.tunombre.miapp",
      "adaptiveIcon": {
        "foregroundImage": "./assets/adaptive-icon.png",
        "backgroundColor": "#ffffff"
      }
    }
  }
}

Basta con sustituir los PNG dentro de assets/ por uno propio (idealmente 1024×1024 para el icono, fondo simple). android.package es obligatorio para poder generar una build de Android — sigue el formato inverso de dominio, por ejemplo com.tunombre.miapp, en minúsculas y sin espacios.

No hace falta diseño profesional

Un icono simple hecho en cualquier editor de imágenes en cinco minutos es más que suficiente para el objetivo de hoy. Lo importante es que exista uno propio, no el icono genérico por defecto de Expo.

EAS Build, paso a paso

EAS (Expo Application Services) es el servicio en la nube de Expo que compila tu proyecto en un APK real, sin necesidad de instalar Android Studio en el portátil. Vamos a generar un APK instalable directamente, sin pasar por Google Play.

1

Inicia sesión con la cuenta de Expo

Desde la terminal integrada de VS Code, dentro de la carpeta del proyecto:

$ npx eas-cli login

Usamos npx en vez de instalar eas-cli de forma global: descarga la versión más reciente cada vez, sin depender de qué tenga instalado cada portátil. Pide el email y contraseña de la cuenta creada en expo.dev.

2

Vincula el proyecto con EAS

$ npx eas-cli init

Crea un proyecto en la cuenta de Expo asociado a este código, y guarda su identificador dentro de app.json (en extra.eas.projectId). Solo hace falta hacerlo una vez por proyecto.

Deberías ver esto

Un mensaje confirmando que el proyecto quedó creado y vinculado, con un enlace a su página en expo.dev.

3

Configura los profiles de build

$ npx eas-cli build:configure

Genera un archivo eas.json en la raíz del proyecto. Un “profile” es simplemente un preset con nombre: define cómo se genera la build (tipo de archivo, para qué está pensada) sin que tengas que repetir opciones en cada comando. Por defecto trae tres: development, preview y production.

Para que preview genere un APK directamente instalable (en vez del formato .aab que exige Google Play), edítalo así:

{
  "cli": { "version": ">= 5.9.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal",
      "android": { "buildType": "apk" }
    },
    "production": {}
  }
}

Hoy solo nos interesa preview. production es para cuando algún día alguien quiera publicar de verdad en las tiendas — eso queda fuera del alcance del curso.

4

Lanza la build

$ npx eas-cli build --platform android --profile preview

El proyecto se sube a los servidores de Expo, donde se compila — tu portátil no hace el trabajo pesado. Puede tardar varios minutos (a veces bastante más si hay cola en el plan gratuito), así que es buen momento para lanzarlo y seguir con otra cosa mientras se procesa.

Deberías ver esto

La terminal se queda mostrando el progreso de la build (subiendo código, esperando en cola, compilando). Al terminar con éxito, imprime un enlace directo de descarga del APK, y también queda visible en el dashboard de expo.dev del proyecto.

5

Instala el APK en el móvil

Con el enlace que dio la terminal, cada alumno lo abre desde el navegador de su propio móvil (o escanea el QR que EAS también ofrece) y descarga el .apk directamente.

Android bloquea por defecto instalar apps fuera de Google Play. La primera vez pedirá permiso explícito — algo como “Instalar apps desconocidas” para el navegador o gestor de archivos usado. Se acepta una vez y ya no se vuelve a preguntar para builds futuras del mismo origen.

Deberías ver esto

Un icono nuevo en el cajón de apps del móvil, con el icono y nombre configurados en app.json — y al abrirla, funciona sola, sin depender de Expo Go ni de que el servidor de npm start siga encendido.

Si algo falla

La build falla pidiendo un “package name” de Android

Falta android.package en app.json. Añádelo (formato com.tunombre.tuapp) y vuelve a lanzar el comando de build.

La cola tarda mucho

El plan gratuito de EAS comparte cola con otros usuarios, así que los tiempos varían — puede ir de unos minutos a bastante más en horas punta. No es un fallo, es simplemente el orden de la cola. Conviene lanzarlo pronto en la sesión para no depender de que termine justo al final.

El móvil dice que no puede instalar el APK descargado

Casi siempre falta activar el permiso “Instalar apps desconocidas” para la app que se usó para descargarlo (Chrome, gestor de archivos…). Se activa desde los ajustes de Android que aparecen enlazados en el propio aviso de error.

¿Esto sirve también para iPhone?

El mismo flujo con --platform ios existe, pero instalar en un iPhone fuera de Expo Go requiere una cuenta de desarrollador de Apple (de pago) o pasos adicionales de registro de dispositivo. Para una clase, quedaos con Android: es el camino directo y gratuito.

Práctica

Cada alumno genera una build de prueba instalable (APK) de su propio proyecto usando eas build --platform android --profile preview, y se la instala en su propio móvil, fuera de Expo Go. Al terminar la sesión, cada uno debería tener la app funcionando como un icono más entre sus apps normales.
