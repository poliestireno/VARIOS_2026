Efectos y formularios

Dos piezas que te van a acompañar en casi cualquier app real: sincronizar un componente con algo externo (un reloj, un fetch, una suscripción) y capturar con garantías lo que escribe la persona que usa la app.

2 horas Sesión 7/24 useEffect + formularios

Todo lo que has escrito hasta ahora vive dentro del ciclo normal de render de React: llega un dato, el componente se dibuja, listo. Pero hay cosas que no encajan en ese ciclo — un temporizador, una petición a un servidor, escuchar un evento del navegador. Son efectos secundarios: cosas que un componente necesita hacer además de simplemente devolver JSX. Y hay otra pieza muy relacionada: los formularios, donde React necesita saber en todo momento qué hay escrito en cada campo. Seguimos en el navegador, con React normal.

Qué vas a aprender

  • Qué es useEffect, cuándo se ejecuta y qué papel juega su array de dependencias.
  • El caso de uso más típico: pedir datos a una API en cuanto el componente aparece en pantalla.
  • Cómo construir un formulario controlado, donde cada input está sincronizado con el estado.

useEffect: cuándo se ejecuta

useEffect recibe una función y, opcionalmente, un array de dependencias. React ejecuta esa función después de pintar el componente en pantalla, y decide si volver a ejecutarla comparando ese array entre un render y el siguiente.

import { useEffect, useState } from "react";

function Reloj() {
  const [hora, setHora] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => setHora(new Date()), 1000);
    return () => clearInterval(id); // limpieza al desmontar
  }, []);

  return <p>{hora.toLocaleTimeString()}</p>;
}

El array al final es la clave para leer un useEffect:

  • [] (vacío) — se ejecuta una sola vez, justo después del primer render. Es el caso típico para “en cuanto aparezca este componente, haz X”.
  • [algoDeEstado] — se ejecuta después del primer render, y luego cada vez que ese valor concreto cambie.
  • sin array — se ejecuta después de cada render, algo que rara vez se quiere de verdad.

La función que return desde dentro del efecto es la limpieza: React la ejecuta antes de repetir el efecto o cuando el componente desaparece de pantalla. En el reloj, evita que sigan corriendo intervalos huérfanos.

El caso de uso estrella: fetch al montar

El uso más habitual de useEffect es pedir datos a una API en cuanto el componente aparece, algo que ya conoces del bloque de JavaScript — ahora solo lo conectamos al estado.

function ListaUsuarios() {
  const [usuarios, setUsuarios] = useState([]);
  const [cargando, setCargando] = useState(true);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/users")
      .then((res) => res.json())
      .then((datos) => {
        setUsuarios(datos);
        setCargando(false);
      });
  }, []);

  if (cargando) return <p>Cargando…</p>;

  return (
    <ul>
      {usuarios.map((u) => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  );
}

El patrón de cargando importa: al principio no hay datos que mostrar todavía, así que el componente renderiza un estado de carga mientras el fetch está en marcha, y cambia a la lista real en cuanto llega la respuesta.

La función del efecto nunca es async directamente

useEffect(async () => {'{ ... }'}, []) es un error habitual: una función async siempre devuelve una promesa, y React espera que el efecto devuelva o nada, o una función de limpieza — nunca una promesa. Si necesitas await, define una función async aparte dentro del efecto y llámala.

Formularios controlados

Un input HTML normal guarda su propio valor internamente, fuera del alcance de React. Un input controlado renuncia a esa memoria propia: su value viene siempre del estado, y cada tecla dispara onChange para actualizar ese estado. React manda en todo momento.

function CampoNombre() {
  const [nombre, setNombre] = useState("");

  return (
    <input
      value={nombre}
      onChange={(e) => setNombre(e.target.value)}
      placeholder="Tu nombre"
    />
  );
}

Con esto ganas algo muy valioso: en cualquier momento sabes exactamente qué hay en el campo (para validarlo, para deshabilitar un botón, para mandarlo a un servidor) sin tener que ir a buscarlo al DOM con document.querySelector.

Para un formulario con varios campos, en vez de un useState por campo suele usarse un único objeto de estado y actualizar una propiedad cada vez, con el patrón de “copiar y sobrescribir” que ya viste con arrays:

const [datos, setDatos] = useState({ nombre: "", email: "" });

function actualizar(campo, valor) {
  setDatos({ ...datos, [campo]: valor });
}

// en el JSX
<input
  value={datos.email}
  onChange={(e) => actualizar("email", e.target.value)}
/>

[campo]: valor es una propiedad computada: el nombre de la clave sale de la variable campo en vez de escribirse literalmente, así una sola función actualizar sirve para todos los inputs del formulario.

Validación básica

Validar en React es, sobre todo, guardar los errores también como estado: un objeto donde cada clave es un campo y cada valor (si existe) es el mensaje de error a mostrar.

function validar(datos) {
  const errores = {};
  if (datos.nombre.trim() === "") {
    errores.nombre = "El nombre es obligatorio";
  }
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(datos.email)) {
    errores.email = "El email no tiene un formato válido";
  }
  if (datos.password.length < 6) {
    errores.password = "La contraseña debe tener al menos 6 caracteres";
  }
  return errores;
}

Con eso, el JSX solo tiene que preguntar si hay mensaje para ese campo y, si lo hay, mostrarlo con renderizado condicional — exactamente el && de la sesión pasada.

<input
  value={datos.email}
  onChange={(e) => actualizar("email", e.target.value)}
/>
{errores.email && <p className="error">{errores.email}</p>}
La idea que se queda de hoy

useEffect conecta un componente con algo de fuera de React, y su array de dependencias decide cuándo se repite. Un formulario controlado hace que el estado sea siempre la fuente de verdad de lo que hay escrito, lo que permite validar en cualquier momento.

Práctica: formulario de registro

1

Monta los tres campos

Un componente FormularioRegistro con tres inputs controlados: nombre, email y password (este último con type="password"), todos leyendo de un único objeto de estado.

2

Añade el estado de errores

Un segundo estado, errores, que empieza como un objeto vacío {'{}'}.

3

Valida al enviar

En el onSubmit del <form> (recuerda llamar a e.preventDefault() para que el navegador no recargue la página), comprueba: ningún campo vacío, el email con formato válido, y la contraseña con al menos 6 caracteres. Guarda lo que encuentres en errores.

4

Muestra los mensajes

Debajo de cada input, muestra su mensaje de error correspondiente solo si existe, con {'{errores.campo &&

...

}'}.

Deberías ver esto

Si envías el formulario vacío, aparecen los tres mensajes de error. Si corriges los campos uno a uno y vuelves a enviar, los mensajes van desapareciendo. Con los tres campos válidos, el formulario se considera correcto (por ejemplo, con un alert("Registro correcto")).

Reto extra

Valida en tiempo real: recalcula los errores del campo cada vez que cambie, no solo al enviar.

Usa useEffect para poner el foco automáticamente en el primer campo con error después de intentar enviar el formulario, con una ref (te la presentamos por encima: useRef guarda una referencia directa a un elemento del DOM).
